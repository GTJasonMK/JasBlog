这些词分别属于语言、浏览器、构建工具或服务端。我把它们分清楚之后，读报错和工具文档会更容易定位到同一层的问题。

| 术语 | 含义 |
| --- | --- |
| API | 程序之间交换数据的接口；这些示例主要使用 HTTP API。 |
| Async / await | JavaScript 中编写异步流程的语法，底层仍基于 Promise。 |
| 编译 | 将源代码转换成目标代码；转译工具不一定执行类型检查，TypeScript 项目仍需单独运行类型检查。 |
| Cookie | 浏览器按域名和策略保存、随请求发送的小段数据。 |
| DOM | 浏览器对 HTML 文档的对象表示，供脚本读取和操作。 |
| 泛型 | 编写可复用代码时保留类型信息的一种参数化方式。 |
| HTTP | 浏览器与服务器常用的请求/响应协议。 |
| Middleware | Express 请求处理链中的函数，可检查或修改请求、响应并继续传递。 |
| npm | Node.js 常用的包管理器。 |
| Prisma | 这些示例使用的数据库 Schema、迁移和查询工具。 |
| React | 用组件构建浏览器用户界面的 JavaScript 库。 |
| REST | 以资源和 HTTP 方法组织 API 的常见设计风格。 |
| Schema | 对数据结构及其约束的描述；Zod Schema 还可以在运行时校验数据。 |
| Type inference | 编译器根据上下文推导类型，减少手工标注。 |
| Type narrowing | 根据条件检查把宽泛类型缩小到更具体的类型。 |
| TypeScript | 为 JavaScript 增加静态类型检查的语言；类型会在运行前擦除。 |
| Vite | 这些示例用于开发和构建 React 前端的工具。 |
| Workspace | 一个仓库中由包管理器统一管理的多个相关项目。 |
