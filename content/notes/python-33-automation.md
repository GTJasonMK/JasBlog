一个脚本第一次跑通之后，我会接着考虑第二次运行会怎样：会不会覆盖结果、重复处理，或者把已经改过的文件再改一次。输入、转换和输出分开，才能逐步把这些情况讲清楚。

Python 常被用来连接文件、命令行程序和 Web API。自动化脚本应把“输入、转换、输出”拆开；重复运行时应得到可预测结果，并记录足够的错误信息。

常用工具：`pathlib` 管理路径，`csv`/`json` 读写常见数据，`argparse` 提供命令行参数，`subprocess` 调用外部工具，`httpx` 访问 HTTP API。Excel 常用 `openpyxl`，HTML 页面解析常用 Beautiful Soup；浏览器自动化可了解 Playwright。

## 典型流程

1. 明确输入来源和字段格式。
2. 校验数据并转换成统一结构。
3. 输出到文件、数据库或 API。
4. 对失败记录日志，并让任务可以安全重跑。

## 批量操作先检查计划和冲突

网页抓取不是任意下载：检查站点条款和访问限制，控制频率，优先使用公开 API。路径和 shell 命令都要避免直接拼入未经校验的用户输入。

## 动手验证

**练习：**批量重命名文件时，怎样避免重复运行产生错误？

**答案：**先计算并打印计划，检查目标名是否冲突，再执行；将规则写成纯函数，并为“目标已存在”定义明确行为。
