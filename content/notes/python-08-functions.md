算一组成绩的平均值，可以在读文件时直接写一遍，生成报表时再写一遍。等到规则要变化，例如空成绩应该报错，两个地方就要一起修改。把计算提取成函数，是为了让这条规则有一个明确的名字和入口，调用者只需要提供约定的数据。

不过，把代码缩进到 `def` 里面还不够。这个函数接收什么，返回什么，什么时候无法完成，都属于它的使用约定。下面先限定输入为一组支持求和、求长度的数值序列：

```python
def average(values):
    if not values:
        raise ValueError("至少需要一个数")
    return sum(values) / len(values)

result = average([3, 6, 9])
print(result)  # 6.0
```

执行 `def` 时，Python 创建函数对象，并把 `average` 这个名称绑定到它。真正执行函数体是在后面的 `average(...)` 调用时。调用中的列表传给参数 `values`，函数计算结果，再通过 `return` 把结果交还给调用位置。

这个例子没有承诺接受任何“看起来像一组数据”的对象。生成器虽然可以迭代，却不能直接用 `len`，而且空生成器对象在条件中通常仍为真。如果要支持任意可迭代对象，就得另行设计遍历计数的算法。说明输入条件，能让调用者知道什么时候可以直接使用这个函数。

## 为什么计算函数要返回结果

把上面的 `return` 换成 `print`，屏幕上也能看到6.0，乍看似乎一样。可是调用者如果还想比较是否达标，就会发现拿不到这个数：

```python
def show_average(values):
    print(sum(values) / len(values))

result = show_average([3, 6, 9])  # 打印 6.0
print(result is None)            # True
```

`print` 把文本写到输出流，`return` 把对象交回调用者。没有显式执行 `return` 的函数会返回 `None`，所以第二行检查得到 `True`。展示函数可以负责打印，计算函数则把数值返回，让终端、网页、测试或报表按自己的需要处理。

`return` 还会立即结束当前调用，后面的语句不再执行。如果要返回多个相关结果，可以返回元组，再由调用者解包，例如 `return total, count`。这仍然是返回一个对象，只是这个对象里包含多个值。

## 空输入为什么没有悄悄算成0

平均值的分母是样本数，空列表没有平均值。直接返回0会把“没有成绩”伪装成“平均分确实为0”，调用者就失去了区分两种情况的机会。

因此，`average` 在前提不满足时抛出 `ValueError`，由接收输入或负责展示的那一层决定怎样提示。异常属于调用约定，并不要求每个函数都先捕获再打印一次。若产品确实需要用 `None` 表示“尚无平均值”，也可以定义那种接口，但所有调用者都必须处理这个分支。

函数的名字也应该与行为一致。名为 `average` 的函数若顺便修改全局成绩单、写文件或发网络请求，就很难从调用处理解代价。操作有副作用时，让名称、参数或文档把这件事说清楚。

## 状态尽量通过参数和返回值传递

调用函数时，参数和函数内部赋值产生的名称通常属于这次调用的局部作用域。函数外面恰好有一个同名变量，也不会被普通局部赋值直接改掉：

```python
count = 10

def increment(count):
    count += 1
    return count

print(increment(count))  # 11
print(count)             # 10
```

这里如果希望外部变量得到新值，就由调用者明确写 `count = increment(count)`。这样在调用处就能看见状态发生了变化。

另一个常见错误是，函数先读取外层同名变量，后面又给它赋值。只要一个名称在函数体中被赋值，且没有通过 `global` 或 `nonlocal` 特别声明，它通常就会被当成本地名称；在它获得本地值之前读取，会出现 `UnboundLocalError`。这解释了为什么“只加了一行 `count += 1`，原来能读的全局变量就报错了”。

`global` 可以声明操作模块级名称，但它也让函数依赖外部状态。多数计算逻辑通过参数接收需要的数据、通过返回值交出结果，更容易重复执行和单独测试。函数仍然可能修改传入的列表或字典，这属于[共享对象](/notes/python-02-objects)的行为，局部参数名并没有替调用者隔离对象内容。

## 一个函数完整到哪一步才合适

“计算文本词数”这个任务也需要说清楚“词”的含义：

```python
def word_count(text):
    return len(text.split())

print(word_count("  hello   python  "))  # 2
print(word_count("   "))                # 0
```

没有给 `split` 传分隔符时，它按空白拆分，并且不会因为连续空白产生一串空字段。因此这段实现适合统计空白分隔的词，输入为空白文本时得到0。

但它不能完成中文分词，也不会把英语标点按语言规则处理。`word_count("你好世界")` 得到1，是当前拆分规则的结果，不是对中文词数的准确判断。把这个限制写出来，才能知道它适合日志中的简单字段统计，还是需要换成真正的分词器。

可以给 `average` 检查普通列表、单元素列表和空列表，再给 `word_count` 检查连续空格与中文。用这些输入确认函数的承诺，比只验证一次“有输出”更能说明它是否满足当前任务。
