计数器调用Add以后还是0，常见原因是方法收到了一份结构体副本。把接收者改成指针，不仅改变能否修改原对象，也改变了哪些类型满足接口。先把复制的对象说清楚，再选择方法形式。

## 函数与返回值

Go 函数可以返回多个值，最常见的用途是同时返回结果和错误。命名返回值适合少数能明显改善可读性的场景，不要把函数写成依赖隐式修改返回变量的形式。

参数按值传递，指针本身也是复制一个地址值。函数给局部指针重新赋值，不会改调用方的指针变量；通过它修改指向的对象，调用方却能看到。切片与map同样要区分变量本身和它描述的共享存储。

defer 会在当前函数返回前按后进先出的顺序执行，适合释放锁、关闭文件和取消 context。defer 调用的参数在 defer 语句执行时求值；不要在长循环里持续 defer 资源关闭，否则资源会等到外层函数返回才释放。

~~~go
func divide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("除数不能为零")
	}
	return a / b, nil
}
~~~

需要导入 errors 包。调用者应显式检查错误，而不是假设结果总是有效。

除零时返回的0只是结果槽位占位，不能在error非nil时继续当有效商使用。整数除法截断小数部分，`divide(5, 2)` 得到2；要保留小数，需要另外定义数值合同。签名表达类型，舍入含义仍要说明。

## 方法与指针

方法是带接收者的函数。值接收者会复制接收者值；指针接收者可以修改原值，也避免复制较大的结构体。一个类型的方法集会影响它是否满足接口，因此应在类型设计时保持一致。

~~~go
type Counter struct{ n int }

func (c *Counter) Add(delta int) {
	c.n += delta
}
~~~

Go 会在可取地址的变量上自动处理常见的 c.Add(1) 调用，但接口实现仍要看方法集。

假设接口要求 `Add(int)`，`*Counter` 满足它，Counter值本身不满足。直接对可取地址变量调用时，编译器可以帮忙取地址；把值放进接口时，不会自动变成指针。这解释了“能调用但赋给接口失败”的现象。

值接收者适合小而独立的值，指针接收者适合需要修改状态或避免复制的对象。含map、切片字段的值接收者仍可能修改共享数据，不能把它当作只读保证。含Mutex等不可随意复制的状态更应统一使用指针。

## 延迟的是调用

`defer fmt.Println(value)` 在声明defer时确定参数，返回前才打印；闭包 `defer func(){ fmt.Println(value) }()` 则在执行时读取捕获变量。多个defer按后进先出运行，资源成功获得后立即安排清理，顺序与资源依赖相符。

循环中每次打开文件都defer关闭，会把文件留到外层函数结束。把单次处理提取成小函数，可以及时释放资源。写文件还要处理Close错误，不能因为写了defer就认为写入已经成功。

## 闭包读到的变量由语言版本和声明方式决定

闭包捕获变量，不必然捕获某一刻的快照。Go 1.22起，在使用新语义的模块中，由循环声明的迭代变量每次分别创建；若变量在循环外声明，再用 `=` 反复赋值，仍是复用同一个变量。核对go.mod和声明位置，不能只看本机工具版本。

并发任务可以显式接收任务参数，让数据来源更清楚。但参数里若含共享指针，复制参数没有消除竞争；同步问题还要沿实际访问路径检查。
