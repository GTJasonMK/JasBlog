两个Task实例标题不同，比较它们的complete方法却可能相等。字段与方法不一定都复制在每个实例上，JavaScript会沿对象的原型链寻找属性。class把构造和方法写在一起，仍然使用这套对象机制。

JavaScript 对象可从原型继承属性和方法。class 语法提供较熟悉的构造、实例方法和继承写法，但底层仍基于原型。组合对象往往比深层继承更容易维护。

~~~js
class Task {
  constructor(title) {
    this.title = title;
    this.done = false;
  }

  complete() {
    this.done = true;
  }
}
~~~

初学者可先用对象和纯函数表达业务，只有需要封装状态与行为时再使用类。异常用 throw 抛出、try/catch 捕获；捕获后应采取明确动作或重新抛出。

`new Task("学习")` 创建实例，constructor设置title与done为自身字段。读取complete时，实例没有同名字段，就从Task.prototype取得方法；通过实例调用时，this指向该实例，因此只修改它的done。

可以用Object.hasOwn检查自身字段，用Object.getPrototypeOf查看原型。hasOwn与直接读取不同：读取可能沿原型找到继承属性，检查外部对象时如果只关心明确提供的字段，应保留这个区别。

把 `const run = task.complete` 取出来再调用，不会自动记住task。需要保持接收者时可以显式bind，或传一个调用 `task.complete()` 的闭包；不要靠类语法猜测方法天然绑定实例。字段箭头函数又会形成不同的每实例函数关系。

## 继承和异常处理都要有明确目的

- class 的方法默认不在实例自身属性中，而在原型上。
- 继承不应只为了复用一小段代码。
- 空 catch 会隐藏错误，不能静默忽略失败。

类适合围绕状态维护持续不变量，例如不允许已归档任务重新完成；纯数据在前后端之间传输时，普通对象通常更直接。JSON序列化不会保存原型方法，服务端返回看似Task形状的对象，客户端不会因此获得complete方法。

继承只有在替代关系和共同合同成立时才有意义。只是两个对象都要格式化标题，可以用函数组合，不必建立多层父类。构造参数无效与状态不允许要走明确错误路径，catch只在能处理、转换或呈现失败的边界使用，不返回假成功。
