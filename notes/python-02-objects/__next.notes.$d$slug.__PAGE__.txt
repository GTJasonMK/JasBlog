先看两段很像的代码。它们都把一个变量赋给另一个变量，后面的结果却不同：

```python
count = 3
other = count
count = 4
print(other)  # 3

items = ["a"]
alias = items
alias.append("b")
print(items)  # ['a', 'b']
```

如果把赋值理解成“复制了一份值”，第二段就不好解释了。`alias` 明明已经赋好值，为什么它添加元素以后，`items` 也跟着变化？

Python 中的赋值把名称绑定到对象。`other = count` 执行以后，两个名称都指向值为 `3` 的那个整数对象。接着执行 `count = 4`，改变的是 `count` 的绑定，`other` 仍指向原来的对象。它不会持续追踪 `count` 后来指向了谁。

列表那段则没有给 `alias` 重新赋值。`append` 修改了两个名称共同指向的列表，所以从 `items` 读取时也会看到新增元素。这里发生的事情是“改了同一个对象”，并没有在两个独立的列表之间同步数据。

## 可变说的是对象，类型也属于对象

整数、字符串、元组等对象不支持改变自身已有的内容。列表、字典、集合则提供了修改内容的操作。这就是可变与不可变的区别。

不过，变量名没有被限定为只能绑定某一种类型：

```python
value = 3
print(type(value))  # <class 'int'>
value = "three"
print(type(value))  # <class 'str'>
```

第二次赋值让 `value` 指向字符串，不是把原来的整数对象变成了字符串。理解这一点，才不会把“Python 不要求提前声明变量类型”误解为“对象没有类型”。函数能不能接收一个对象、对象支持什么操作，仍然受它的类型影响。

## 值相等，不代表是同一个对象

另一个容易混在一起的问题是：内容一样，算不算同一个？

```python
a = [1, 2]
b = [1, 2]
c = a

print(a == b)  # True
print(a is b)  # False
print(a is c)  # True
```

`==` 比较两个对象的值是否相等，具体规则由类型定义；`is` 比较它们是不是同一个对象。这里创建了两个列表，它们内容相同、身份不同。修改 `a` 会影响 `c`，却不会影响 `b`。

检查 `None` 时使用 `value is None`，因为这里想确认的就是这个特定对象。比较数字或字符串的内容则用 `==`。某些解释器会复用部分整数和字符串对象，碰巧出现的身份相同不能成为业务判断依据。

`id(obj)` 可以帮助观察对象身份，在对象存活期间保持不变；它不是业务ID，也不保证对象被回收以后这个值不再被使用。要给订单或用户编号，仍然需要自己的标识。

## 一次赋值会不会改原数据，要看右边做了什么

回到列表，再看下面这段：

```python
a = [1]
b = a
b = b + [2]
print(a, b)
```

这次得到的是 `[1] [1, 2]`。右边的 `b + [2]` 先生成一个新列表，随后 `b` 指向这个新对象，`a` 仍指向原来的 `[1]`。

如果把那一行写成 `b += [2]`，对于内置列表，增强赋值会原地扩展列表，两个名称看到的就都是 `[1, 2]`。因此不能把所有 `+=` 都机械地理解为先计算 `b + ...` 再赋值；对象类型可以定义不同的原地操作。

这也是读代码时值得停一下的地方。看到一个调用或运算，问清楚它是返回新对象，还是修改已有对象，很多“数据怎么突然变了”的问题就有了线索。

## 把对象传给函数，共享关系还在

函数参数同样会绑定到传入的对象：

```python
def add_tag(tags):
    tags.append("python")

def replace_tags(tags):
    tags = ["new"]
    return tags

original = ["study"]
add_tag(original)
print(original)                # ['study', 'python']
print(replace_tags(original))  # ['new']
print(original)                # ['study', 'python']
```

`add_tag` 通过参数修改了那个列表，调用者当然能看到变化。`replace_tags` 只让局部名称指向另一个列表，调用者的 `original` 不会随之改绑。这种调用规则常称为对象共享，或者按赋值传参。

它什么时候有用？写数据清洗函数、维护一份公共配置，或者把缓存中的字典传给其他函数时，都需要明确谁可以修改对象。如果调用者希望原数据保留，就让函数返回新结果，或在合适的层次创建副本。具体复制到哪一层，会在[浅拷贝与深拷贝](/notes/python-27-references-copy)里展开；先确定共享关系，再考虑复制方法。

可以把上面函数里的列表换成整数试试。让函数执行一次 `count += 1`，观察调用者的变量是否变化，再用“修改对象”和“重新绑定”分别解释结果。能解释清楚这两种情况，比背一个“可变类型会变”的结论更可靠。
