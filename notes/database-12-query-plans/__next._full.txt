## 从业务症状缩小到具体 SQL

接口慢可能来自连接池等待、网络、锁、执行计算或返回数据过多。先分清耗时位置，再确定 SQL、参数、调用频率、返回行数和数据库负载。一次执行慢与一条很快但每秒执行数万次的语句，需要不同判断。

```sql
SELECT queryid, calls, total_exec_time, mean_exec_time, rows,
       shared_blks_hit, shared_blks_read, query
FROM pg_stat_statements
ORDER BY total_exec_time DESC LIMIT 10;
```

`pg_stat_statements` 是按语句归一化聚合的历史统计，`mean` 不是 p95，采样区间也可能包含不相关的历史。不要随便重置共享统计；保存起止快照计算增量。访问完整查询文本需要适当权限，日志和输出要防止敏感值泄露。

## 读懂计划的几个数字

```sql
EXPLAIN (ANALYZE, BUFFERS, SETTINGS)
SELECT id FROM shop.orders WHERE customer_id = 1;
```

`EXPLAIN` 只展示估计计划，`ANALYZE` 会真正执行。对写语句、带副作用的函数、序列、外部调用要特别谨慎；即使外层回滚，也不保证所有副作用消失。生产先取不执行的计划，再决定是否允许实际运行。

| 字段 | 解释 |
|---|---|
| cost | 优化器的相对估计成本，不是毫秒 |
| rows | 节点估计输出行数 |
| actual time / rows / loops | 实际时间、每次循环的平均输出行数和循环数 |
| Buffers hit / read | 共享缓冲命中和读入，不直接等于磁盘 I/O 次数 |
| Rows Removed by Filter | 读到后又过滤的行，可能说明工作量过大 |
| Sort Method / Disk | 排序算法与是否使用临时磁盘 |
| Heap Fetches | 覆盖扫描仍要回表验证可见性的次数 |

从叶子向上看输入、输出与循环次数。actual rows为10、loops为1000，表示反复处理后的工作量不能只看那个10；节点时间又常包含子节点，整棵树直接相加会重复计算。先确认数字的口径，才谈热点在哪。

## 理解常见节点

顺序扫描适合小表或大量匹配；索引扫描适合有选择性的定位；位图扫描可以组合条件并按块回表。Nested Loop 对小外表和高效内层定位合适，外层过大时内层执行次数会放大；Hash Join 适合等值连接但可能溢出到磁盘；Merge Join 依赖有序输入。

出现 Seq Scan 不直接等于缺索引，出现 Index Scan 也不等于高效。三行订单表选择顺序扫描很合理。

估计只来几行，实际来了几十万行，原本便宜的Nested Loop可能变得昂贵。先查统计与参数分布，再考虑索引或连接策略；强制关闭某种扫描让计划好看，没有解释优化器为什么判断错。

## L4：20 万行前后对比

按[实验手册](/notes/database-lab-guide)执行 `05-performance.sql`。它用确定性数据建立练习表，先分析无目标索引计划，再建立联合覆盖索引并重跑完全相同的查询。

保存前后访问方式、扫描与过滤行数、缓冲区访问、排序、执行时间和索引大小。再独立运行同一查询至少 5 次，报告中位数与范围。先后的缓存状态不同，因此不能只用第一遍和第二遍的耗时计算“加速倍数”。

前后查询结果也要一致。若少取了状态或漏了排序，速度改善可能来自问题已经变了；比较先固定语义，再看索引是否把扫描与排序缩到合理范围。首次运行还承担更多读取，重复测量才帮助区分结构收益与缓存差异。

本实验每客户固定 200 条记录，部分客户状态与编号相关，这种规则分布便于核对结果，也限制了对真实倾斜数据的代表性。线上优化要包含大客户、小客户、空结果和热点状态。

## 按原因优化

估计偏差先检查统计更新、列相关性和参数分布，必要时评估扩展统计。扫描太多时检查筛选和索引。关联放大先修正结果粒度。排序溢出先减少排序输入、检查索引，再评估内存；不能直接把全局 `work_mem` 放大，因为单查询多个节点、多个并发连接会同时使用它。

修复后核对结果一致、读写延迟、WAL、空间、复制延迟与并发。只降低单条查询耗时而明显拖慢写入，不一定满足业务目标。

接口慢如果实际发生在池等待或锁等待，就回到相应路径，不继续在计划上找不存在的CPU热点。计划是一段执行证据，需要和请求时间线、参数与负载连接，才能解释用户的等待。

## 动手验证

提交完整前后计划与解释。再把筛选客户换成多个值，说明是否仍受益。不要关闭顺序扫描强迫计划“看起来正确”。
