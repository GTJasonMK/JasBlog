假设要从一行 `"  Ada,96  "` 中取出姓名和成绩。看起来只是拆两个字段，实际已经包含几件事：去除首尾空白、按分隔符拆开、把成绩转成数字，最后组织成展示文字。

Python 的 `str` 用来表示 Unicode 文本，它支持按位置读取和按规则产生新文本。先把最基本的读取方式试清楚：

```python
text = "Python 教程"
print(text[0])       # P
print(text[-2:])     # 教程
```

索引从0开始，负数从末尾算起。`text[-2:]` 表示从倒数第二个位置一直取到结尾，所以结果是“教程”。完整的切片写法是 `text[start:stop:step]`，其中 `stop` 所在的位置不包含在结果中。`text[:6]` 取前六个位置，不需要再把终点减一。

单个索引超出范围会报 `IndexError`，切片的边界则会按序列长度调整。例如 `"abc"[:100]` 仍然得到 `"abc"`。如果本来就应该存在某个字段，别因为切片没有报错，就以为输入一定完整。

## 修改字符串会产生新值

字符串不可变，所以 `text[0] = "p"` 不被允许。`strip`、`replace`、`lower` 等方法也不会原地改掉原对象，而是返回处理结果：

```python
raw = "  hello python  "
cleaned = raw.strip().title()
print(raw)      # 原字符串仍有首尾空格
print(cleaned)  # Hello Python
```

因此，单独调用 `raw.strip()` 而不使用返回值，不会得到一个“从此已经清理”的 `raw`。需要保留结果时，可以赋给新变量，也可以重新绑定原变量。

`strip()` 去掉两端空白，不处理文本中间的空格。如果给它传入 `"ab"`，含义是去掉两端连续出现的 `a` 或 `b` 字符，不是删除完整前缀 `"ab"`。确实要去掉一个已知前缀时，`removeprefix` 的语义更合适。

回到开头的输入：

```python
record = "  Ada,96  "
name, score_text = record.strip().split(",")
score = int(score_text)
print(f"{name} 得分 {score:.1f}")  # Ada 得分 96.0
```

`split` 负责拆分，`int` 负责解析整数，f-string 负责展示。这里假定输入只有两个不含逗号的字段；多一个字段会导致解包失败，成绩不是整数也会报错。把输入格式限制说出来，例子才算完整。真正的CSV文件还允许引号和字段内的逗号，那时应该使用 `csv` 模块解析，而不是一直往 `split` 外面补条件。

## 格式化解决展示，不能代替数据处理

`f"{score:.1f}"` 把数值显示为一位小数，但 `score` 自身仍是原来的数字。显示格式、计算精度和保存方式是三回事。例如格式化为两位小数并不会把浮点计算变成精确的金额运算，金额的类型选择见[上一篇](/notes/python-03-basic-types)。

拼接少量文本直接用 `+` 就能看懂；从许多记录组织报告时，可以先收集片段再用 `"\n".join(lines)`。字符串不可变，在循环里反复构造越来越长的字符串可能产生较多复制开销，`join` 把“收集内容”和“组织最终文本”分开，也更便于调整分隔符。

## 文本离开程序时，需要一种字节表示

现在看另一个常见现象：

```python
text = "你好"
data = text.encode("utf-8")
print(len(text))                  # 2
print(len(data))                  # 6
print(data.decode("utf-8") == text) # True
```

`str` 的长度按Unicode码点计算；`bytes` 的长度按字节计算。这两个汉字在UTF-8中各使用三个字节，所以结果不矛盾。某些表情或组合字符还会由多个码点组成，用户看到的一个符号也不一定只占一个字符串位置。做界面字数限制、截断表情时，需要进一步考虑完整字形。

编码把文本转换为字节，解码再按某种规则把字节还原为文本。读取文件应使用文件实际采用的编码，例如 `open(path, encoding="utf-8")`。如果原文件采用其他编码，硬套UTF-8并不会让它自动变成UTF-8文件。

遇到解码错误时，直接设置 `errors="ignore"` 会丢弃无法识别的字节。结果虽然看起来能继续处理，原数据却已经少了一部分。先确认数据来源和编码，再决定怎样处理坏输入；日志、导入文件和网络响应，都需要保留这条线索。

可以用一份同时包含英文、汉字和表情的短文本做个验证：分别观察字符串长度、UTF-8字节长度，再编码和解码一次，确认原文能够完整还原。处理文本时记住当前拿到的是文字还是字节，后面的文件和网络操作就更容易解释。
