代码里直接new Date，测试到活动结束点时就得想办法控制真实时间。若业务只需要“给我现在这个时间”的能力，可以传入Clock，把变化来源从规则里拆出来。接口约定能力，类提供实现，两者不用建立深继承关系。

TypeScript 类可声明字段类型、构造参数和方法类型；implements 检查类是否满足接口。abstract 类不能直接实例化，可包含共享实现。public、private、protected 主要约束静态访问。

~~~ts
interface Clock {
  now(): Date;
}

class SystemClock implements Clock {
  now(): Date {
    return new Date();
  }
}
~~~

参数属性可在构造参数上使用 readonly 等修饰符。私有字段的运行时保护与普通 private 关键字不同，具体需求应选合适机制。

implements检查SystemClock实例具有now方法，返回Date；删掉方法应编译失败。它不会把接口方法自动生成到类中，也不会根据接口给所有实现参数反向补上正确注解。业务接收Clock，测试提供固定返回值的对象就可以，不一定必须再写一个类。

抽象类适合确实共享实现与状态的类型族，子类仍负责抽象部分；只有一项可替换能力时，小接口通常更直接。readonly字段限制重新赋值，不自动冻结字段指向的对象，运行时规则仍须对应实际可变状态。

## private与井号字段的不同

TypeScript的private主要限制静态访问，转成JavaScript后不能把它当作秘密保护。ECMAScript的#字段在运行时具有私有访问机制，但也不能让已经交给浏览器的密钥成为安全秘密。封装对象内部状态与服务端资源授权是不同边界。

参数属性把构造参数同时声明为字段，减少重复赋值，但会涉及运行时代码生成；某些只剥离类型的运行方式不支持所有这类语法。选择代码写法时，核对实际构建与运行工具，不只看tsc能否接受。

固定时钟测试先让活动开始前返回无效，再让同一规则在开始点有效。这样测试控制的是时间输入，系统时钟实现则单独承担获取时间的工作。类与接口的收益体现在这条可解释的依赖关系上，而不是声明数量。

## 声明约束不会自动生成实现

- implements 不会自动把接口属性生成到类中。
- private 的类型限制不等于授权或安全边界。
- React 组件通常使用函数组件，不需要写 class 组件。

## 动手验证

定义一个 Clock 接口和固定时间的测试实现；让业务函数依赖接口，而不是直接调用系统时间。
