如果目标只是把一张表按地区汇总，不需要先学习桌面框架；如果希望别人点一下按钮就完成任务，只有一个分析函数又不够。语言基础相同，应用方向的差别常常在输入由谁提供、任务怎样启动、结果交给谁。

这一篇不再按库名挨个背功能，分别拿网页标题、Excel行、按钮点击和曲线拟合看它们怎样进入程序。例子只覆盖各自写明的输入，不把几个片段拼成一个通用自动化系统。

网页采集#

优先查找公开 API；读取 HTML 时可用 httpx 请求、Beautiful Soup 解析。设置超时，检查 HTTP 状态，并遵守站点规则与访问频率。

python
import httpx
from bs4 import BeautifulSoup

response = httpx.get("https://example.com", timeout=10)
response.raise_for_status()
soup = BeautifulSoup(response.text, "html.parser")
print(soup.title.get_text(strip=True) if soup.title else "无标题")

安装：python -m pip install httpx beautifulsoup4。如果页面内容由 JavaScript 渲染，静态 HTML 可能不含目标内容；先检查 API，再考虑浏览器自动化工具。

HTTPX拿到的是服务器返回的文本，Beautiful Soup负责把文本解析成可查找的树。soup.title 可能不存在，所以先检查；存在时 get_text(strip=True) 提取内容并去掉两端空白。标题不存在是一种明确的数据状态，不能与网络失败、服务器500混成同一个“空结果”。

采集多页时还需要页码或游标规则、频率限制和恢复位置。网页样式或结构改变会让选择器失效，应该保留少量固定HTML样本测试解析，不让每次测试都依赖远程站点。内容由脚本生成时，浏览器自动化才会涉及真实渲染和等待条件。

Excel 办公文件#

openpyxl 读取和写入 .xlsx；read_only=True 适合大表扫描，data_only=True 读取 Excel 已保存的公式结果。

python
from openpyxl import load_workbook

book = load_workbook("sales.xlsx", read_only=True, data_only=True)
try:
    sheet = book["Sales"]
    for row in sheet.iter_rows(min_row=2, values_only=True):
        print(row)
finally:
    book.close()

安装：python -m pip install openpyxl。读取 data_only=True 时，公式结果取决于文件是否由电子表格软件重新计算并保存。

values_only=True 只返回单元格值，适合逐行转换；需要格式、坐标或公式文本时，则要读取单元格对象。min_row=2 假定第一行是表头，这也是输入合同的一部分。真实表格可能有合并单元格、空行、隐藏工作表，不能仅凭扩展名就认为每行结构一致。

openpyxl不会代替Excel运行公式。没有缓存结果时，data_only可能读到None，不能直接按0累计。改写工作簿还要选择新文件名或明确覆盖策略；读取与写入是不同风险的动作，演示里只读取并在finally关闭文件。

桌面 GUI#

小型桌面工具可从标准库 Tkinter 入门。GUI 事件循环负责响应点击；事件回调应快速结束，长任务需放到工作线程并把界面更新交回主线程。

python
import tkinter as tk

root = tk.Tk()
root.title("计数器")
count = tk.IntVar(value=0)
tk.Label(root, textvariable=count).pack(padx=16, pady=8)
tk.Button(root, text="加一", command=lambda: count.set(count.get() + 1)).pack()
root.mainloop()

mainloop 持续取出窗口事件，按钮的 command 保存一个以后才调用的函数。若写成 command=count.set(...)，就会在创建按钮时执行，而不是点击时执行。IntVar 把状态与Label关联，修改变量后界面才能显示新值。

如果按钮回调直接下载一个大文件，事件循环得不到处理机会，窗口就像卡死了一样。后台工作应与界面状态分开，通过主线程接收结果和更新控件。Tkinter还依赖系统Tk支持与图形显示环境，服务器上能导入模块不等于能打开窗口。

科学计算#

NumPy 提供数组运算；SciPy 在此基础上提供优化、统计和信号处理等算法。数值计算前应确认单位、数据范围和误差容忍度。

python
import numpy as np
from scipy.optimize import curve_fit

x = np.array([0.0, 1.0, 2.0, 3.0])
y = np.array([1.1, 2.9, 5.2, 6.8])
line = lambda x, slope, intercept: slope * x + intercept
parameters, _ = curve_fit(line, x, y)
print(parameters)  # 拟合得到斜率和截距

安装：python -m pip install numpy scipy。分析结果还应检查残差和模型假设，不能只看拟合参数。

这里的模型是 y = slope × x + intercept，curve_fit 选择参数，使预测与观测之间的平方误差尽量小。斜率的单位是y单位除以x单位，截距与y同单位；拟合得到参数，不代表已经证明x造成y变化。

可以再计算 y - line(x, *parameters) 查看残差。若残差随x有系统变化，直线可能没抓住结构；若只是想在训练点之间插值，也不应把直线无限外推。算法完成优化，与模型是否符合问题，是两次判断。

LLM 服务调用#

不同服务的 URL、请求体和响应字段并不统一；把服务差异放在一个客户端函数内，设置超时、检查状态、验证响应，并从环境变量读取凭证。

python
import os
import httpx

api_url = os.environ["MODEL_API_URL"]
api_token = os.environ["MODEL_API_TOKEN"]
response = httpx.post(
    api_url,
    headers={"Authorization": f"Bearer {api_token}"},
    json={"input": "用一句话解释 Python 列表"},  # 按服务商接口调整
    timeout=30,
)
response.raise_for_status()
result = response.json()

不要把密钥写进源码或 Notebook。对模型输出仍要按应用要求验证；输出文本不能直接当作可信指令或 SQL 执行。

这段只演示HTTP调用的形状，不承诺任何服务都接受 input 或使用Bearer认证。实际客户端应固定服务合同，校验返回字段，再把应用需要的内容交出去。生成任务发生超时，也不能直接推断服务没执行；重试是否重复扣费或重复生成，要按服务提供的请求标识与幂等机制处理。

这些方向最后都会回到相似的问题：外部状态怎样进入程序，纯计算怎样独立验证，什么时候产生副作用。网络等待多时可以考虑线程或异步客户端，数组计算先看向量化，Excel解析则先测量CPU与内存。选择跟着实际任务走，不需要为了“学完整个生态”先安装所有库。
