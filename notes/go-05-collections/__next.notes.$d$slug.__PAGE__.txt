## 切片

切片包含指向底层数组的引用、长度和容量。复制切片变量并不一定复制元素；两个切片可能共享底层数组。需要独立数据时使用 slices.Clone（Go 1.21 起）或显式复制。

数组的长度属于类型，`[3]int` 与 `[4]int` 不同，赋值会复制数组元素；`[]int` 则是切片，长度可变，复制描述信息以后仍可能指向同一个数组。切片常用于数量变化的一组记录，数组适合固定长度的数据。

~~~go
values := []int{10, 20, 30}
view := values[:2]
view[0] = 99 // values[0] 也变为 99
copyOfValues := append([]int(nil), values...)
~~~

追加时如果容量不足，运行时会分配新数组，因此不要依赖扩容后的底层地址。

例子中的view只暴露前两个元素，但还有容量时，向它append可能直接写到原数组的第三个位置。`append` 总会返回新的切片描述，应该接住返回值；底层数组是否更换由容量等条件决定，不应把某次扩容规律当成业务保证。

显式复制或 `slices.Clone` 只复制当前元素。如果元素本身是指针、map或另一个切片，内部对象仍可能共享。要不要深复制，取决于调用方需要隔离哪一层状态，不能看到Clone就认为整张对象关系都隔离了。

## 映射

~~~go
counts := map[string]int{"ok": 2}
counts["failed"]++

value, exists := counts["missing"]
if !exists {
	fmt.Println("没有该键", value)
}
~~~

读取不存在的键会得到零值，所以需要用逗号 ok 判断键是否存在。普通 map 不能被多个 goroutine 同时读写；并发场景需要互斥锁或适当的并发结构。

nil map 可以安全读取，但不能写入；写入前要用 make 或 map 字面量初始化。map 的遍历顺序未定义，测试和业务逻辑不能依赖某次迭代顺序。

counts中明确保存0与根本没有这个键，单值读取都得到0；只有第二个exists能区分。缓存也常有相同问题：找不到记录与查到一个空值不是一回事。map按键查找适合索引与计数，需要有序展示时把键收集后排序，不靠某次迭代刚好稳定。

并发保护要覆盖共同读写同一份map的全部路径。给写函数加锁，而读函数直接读取，依然存在数据竞争；每个goroutine分别创建自己的map则是另一种隔离方式。

## 字符串

字符串是字节序列，UTF-8 下一个汉字通常占多个字节。按字符处理时要使用 range 或 []rune；按协议长度或网络数据处理时往往要按字节。

`len("你好")` 是6个字节，range遍历得到两个Unicode码点，索引值是各码点的起始字节位置。rune是码点，不一定等于用户眼中的一个完整字符，组合音标与部分emoji可能包含多个码点。要实现编辑器里的光标移动或按可见字符截断，还需要字素簇规则。

字符串不可修改；转成 `[]byte` 或 `[]rune` 再处理，会涉及另一份可变表示。按字节截断UTF-8可能切到一个编码中间，适合协议长度的操作不一定适合用户界面。先说明“长度”到底指什么，再选择API。

统计一段文本中每个 Unicode 字符的出现次数。再尝试用 len(text) 统计汉字数量，解释为什么结果与字符数不同。
