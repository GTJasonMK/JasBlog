Go 03：读懂 Go 程序：包、声明与入口

Go语言与工具链

目录

  • 阅读代码的顺序
  • 声明、赋值和换行各有规则
  • 动手验证

同一段代码放进函数可以编译，移到文件最外层却不行，常见原因就是用了 :=。Go把声明放在哪里、名称在哪个范围内有效，都作为语言规则处理，不是换一种排版而已。

同一个目录下的 Go 源文件通常属于同一个包。可执行程序使用 package main，并由 func main() 作为入口。包名是源码中的名字，模块路径是其他包导入它时使用的路径，两者相关但不是一回事。

go
package main

import "fmt"

const serviceName = "order-api"

func main() {
	message := "启动 " + serviceName
	fmt.Println(message)
}

短变量声明 := 只能用于函数内部；包级变量和常量使用 var、const。标识符首字母大写表示对其他包可见，小写表示仅包内可见。Go 没有类继承式的访问修饰符。

程序先初始化依赖包，再初始化当前包的包级状态，最后进入main。不要把连接数据库、读取大量文件等不可控动作随意放进包初始化，否则调用方一导入包就承担副作用，测试也难以选择何时启动。需要失败处理与资源关闭的动作通常在入口显式完成。

名字的范围会改变赋值对象#

value := 1 在当前块创建变量，之后用 value = 2 修改已有变量。同一块里再次单独写 value := 2 会失败，因为没有新变量；value, err := load() 则可能成立，前提是左侧至少一个非空名称在当前块中是新声明。

若进入新的if块，再写 value := 2，会创建内层同名变量。块结束以后，外层值仍然是1。处理 err 时尤其要留心这个遮蔽现象：以为更新了外层错误，实际修改的是短暂的内层变量。判断作用域要看块和声明位置，不只看拼写是否相同。

声明变量但不显式赋值时会获得类型零值：数字为 0、bool 为 false、string 为空字符串，指针、map、slice、channel、函数和接口为 nil。零值可用性是 Go API 设计的重要部分；使用 nil 前要确认该类型的操作是否允许 nil。

例如nil切片可以追加，nil map可以读取但不能直接写入，nil channel上的发送与接收会一直阻塞。它们都叫nil，并不具有同一套可操作规则。一个字段的零值若与业务上的“未设置”不同，也要单独表达，例如用指针区分省略的数量与明确传入的0。

阅读代码的顺序#

先确定文件所属包，再找入口或被调用的导出函数，沿参数和返回值跟踪状态。一个包可以分散在同目录多个文件中，读取业务逻辑时不必只盯着当前文件；导出与否按包边界判断，文件之间通常不需要再声明公开关系。

声明、赋值和换行各有规则#

  • Go 的分号通常由编译器自动插入；不要把换行任意放在表达式中间。
  • 未使用的局部变量和导入会导致编译失败，这是有意设计的反馈。
  • := 如果左侧没有新变量，会报错；它不是赋值运算符 = 的通用替代。

多行字面量在结束前通常要保留尾逗号，左花括号也应遵守Go的换行约定。编译器会自动插入部分分号，任意移动换行可能改变解析。先让gofmt处理格式，剩余时间用来检查名称指向哪个值和调用是否有副作用。

动手验证#

定义模块名、服务名称和端口常量，在 main 中打印服务启动信息。尝试把常量移到函数外，再将变量声明移到函数内，观察 := 的作用域限制。
