这份记录保留原资料在 2026 年 11 月 13 日的 PostgreSQL 实验结果，包括并发、索引前后对比和恢复观察。下面的数字对应当时的临时环境，本次整理没有重新运行数据库实验。

原记录说明所有写入均在单独创建的临时实例和数据卷中完成，未连接既有业务库，验证后已清理临时环境。重新操作时，按[实验手册](/notes/database-lab-guide)启动自己的环境。

## 实测环境

- PostgreSQL：`16.15 (Debian 16.15-1.pgdg13+2)`。
- Docker Engine：29.8.1；Docker Compose：5.5.1。
- 使用本机已有 `postgres:16` 镜像，实测摘要为 `postgres@sha256:ca0bd484cb98bf4b24eb1010e73fb3fcbd6714d240fbc1a10eea5b7dbecb641d`。
- 默认隔离 Read Committed；使用虚构订单数据与 20 万行确定性性能数据。

`postgres:16` 会推进补丁版本；上述版本和摘要只描述当时这次运行。新环境应记录自己的版本并重跑自检。

## 已通过的验证

| 项目 | 实际结果 |
|---|---|
| Compose 配置与初始化 | 两份配置可合并；新库完成 schema、约束、索引与种子初始化 |
| `02-checks.sql` | 7 张业务表行数、59700 分已支付金额、订单明细、支付和库存流水核对通过 |
| `03-place-order.sql`、`04-order-checks.sql` | 正常创建、重复请求、请求内容冲突、缺货、零数量和空参数断言通过，业务自检写入回滚 |
| 并发同请求 | B 等待 A 提交后返回同一订单；初始库存 10，最终库存与流水余额均为 9，只生成一单 |
| 并发抢最后库存 | 两个不同请求键各买一件，只有一单成功；另一个以 `P0001` 失败，最终库存和流水余额均为 0 |
| `05-performance.sql` | 创建并核对 20 万行，索引前后查询成功，返回结果一致 |
| `06-security-checks.sql` | 允许读取规定对象，拒绝更新、原始客户表读取和业务 schema 建表 |
| 真实密码连接 | 通过 TCP 以独立只读账号登录，查询成功，写入被拒绝；临时账号随后移除 |
| 正文 SQL | 第 4、5、6 章全部 SQL 代码块执行成功；错误关联得到 99500 分，正确查询得到 59700 分 |
| 操作手册 | 所有 SQL 代码块在管理员实验身份下执行成功 |
| 发布迁移 | 第 20 章加列、回填、验证与非空收紧执行成功，非法值和空值被约束拒绝，合法值可写入后回滚 |
| 隔离级别 | RC 两次读取为 100、200；RR 为 100、100；RR 写偏斜导致零人值班，Serializable 以 `40001` 拒绝冲突事务 |
| 死锁与 DDL 等待 | 反向更新两行触发 `40P01`，事务均回滚；被阻塞 DDL 达到等待上限后以 `55P03` 失败 |
| 逻辑恢复 | 自定义格式 dump 恢复到独立新库，无恢复错误，新版基线检查通过 |
| 物理备份 | `pg_basebackup -X stream` 完成，`pg_verifybackup` 返回 `backup successfully verified` |
| 命名恢复点 PITR | 源库标记为 1、3；独立恢复实例为 1、2，`pg_is_in_recovery()` 为 true，回放状态 `paused` |
| 数据持久化 | `stop/start` 与 `down/up` 后业务数据和恢复标记保留，基线检查再次通过 |

逻辑恢复使用的是基线数据；并发实验使用独立客户和商品，不将已变动的夹具误判成种子校验失败。

## 性能实验的五轮观察

同一表、同一查询与参数，索引前后各运行五次。表记录 200000 行，目标客户匹配 200 行，返回最新 20 行。

| 条件 | 五轮执行时间，毫秒 | 中位数，毫秒 | 根节点报告的共享块访问 |
|---|---|---|---|
| 无目标联合索引 | 7.900、9.086、12.477、9.010、8.266 | 9.010 | 每轮 1736 次 hit |
| 建立目标联合覆盖索引后 | 0.101、0.077、0.049、0.083、0.047 | 0.077 | 首轮 4 hit + 3 read，后续每轮 7 hit |

无目标索引计划包含并行顺序扫描与排序；目标索引后为 Index Only Scan。索引占用 11796480 字节。这里没有测量持续写入成本，不能用这张表证明生产吞吐或跨环境加速倍数。

共享块访问是计划中的缓冲区统计，不直接代表物理磁盘 I/O；冷热缓存、后台维护和主机其他任务影响时间。正文保留这些解释，避免只背某次毫秒数。

## 恢复观察的边界

原记录中的小库物理备份约 2.252 秒；独立恢复容器从启动到确认暂停与数据正确约 3.189 秒。这些不是完整事故 RTO，不包含发现、调取异地副本、审批、业务切换与真实大数据量恢复。

教学归档、基础备份与源库共用同一数据卷，只验证日志重放机制。没有验证卷或主机损毁、跨地域恢复、自动故障选举、防双主执行、生产 TLS、真实支付或 MySQL 8.4 实例。

MySQL 专章提供版本明确的练习与官方资料，尚未作为已实测环境计入。应用驱动片段用于说明事务与参数绑定接口，也未作为完整应用运行。
