Python 05：列表、元组和解包该怎么选

Python语言基础

目录

  • 元组固定的是元素关系
  • 遍历时只取需要的信息
  • 排序以后，原来的顺序还要不要保留

一份成绩单里有多少人成绩达标，二维坐标的横纵坐标分别是多少，某个操作需要执行几次，这些问题都涉及“一组值”。不过，成绩单需要不断增删，坐标通常按固定位置解释，循环次数则没必要全部存成一张表。它们适合用不同的序列表示。

序列最直接的特征是有位置顺序，可以按索引取值，也可以逐个遍历。列表、元组、字符串、range 都支持这些操作，但它们对修改和存储方式的约定不同。

列表适合一组会继续变化的记录#

python
scores = [81, 92, 75]
scores.append(88)
scores[0] = 85
print(scores)  # [85, 92, 75, 88]

列表保存元素的顺序，也允许替换元素、增加元素和删除元素。append 在末尾添加一个对象，extend 则把另一个可迭代对象中的元素逐个加入。items.append([3, 4]) 加进去的是一个列表，items.extend([3, 4]) 加进去的是两个整数，结果的层次不同。

CPython 的列表使用动态数组。按位置读取通常很快，末尾追加的均摊成本也较低；在开头插入或删除元素，则需要移动后面的引用。因此小型数据列表直接使用列表很方便，频繁从头取出任务的队列更适合 collections.deque。数据结构的选择应对应实际操作，而不只看写起来哪个顺手。

scores[1:3] 可以取中间两项，得到新的列表。不过这只复制外层引用，如果里面还有可变对象，它们仍然会共享。比如复制一组学生字典后，修改某个学生的字典，原列表里的同一个字典也会变化。需要隔离到什么程度，见浅拷贝与深拷贝。

元组固定的是元素关系#

如果一份数据的两个位置分别代表横坐标和纵坐标，元组能够表达这种固定结构：

python
point = (3, 5)
x, y = point
print(x, y)  # 3 5

single = (3,)
print(type(single))  # <class 'tuple'>

解包把右边的值按顺序绑定到左边的名称，减少了反复写 point[0] 的需要。只有一个元素时要保留逗号，(3) 只是带括号的整数表达式。

元组不能把第一个元素从3替换成4，但它不会递归冻结内部对象。([1], [2]) 中的列表仍然可以追加元素。这一点也影响它能否成为字典键：只有内部各项都可哈希的元组，才可用于这种场景。

两个坐标值很容易记住顺序，若数据变成姓名、年龄、邮箱、状态、权限等多个字段，位置含义就不再直观。此时字典、命名元组或数据类往往更好读，不必为了“结构固定”坚持使用普通元组。

解包还可以让一个名称接住中间剩余的值：

python
scores = [81, 92, 75, 88]
first, *middle, last = scores
print(first, middle, last)  # 81 [92, 75] 88

带星号的 middle 得到一个列表。没有星号时，两边数量必须一致；有星号也要能满足其他位置需要的元素数。收到一条外部记录时，解包失败可能说明格式不对，不应该默认把多出来的字段扔掉。

遍历时只取需要的信息#

要逐个处理成绩，直接 for score in scores 就能得到每个数。需要给输出编号时，再增加位置：

python
scores = [81, 92, 75]
for number, score in enumerate(scores, start=1):
    print(number, score)

enumerate 同时提供计数和元素，不需要先取得长度，再用下标查回元素。如果任务只是重复三次，则可以写 for index in range(3)。range 保存起点、终点和步长，按需计算整数，不会预先创建三个、三千个或更多整数对象组成的完整列表。

range(1, 5) 产生1到4，终点同样不包含在内。需要倒序时可以指定负步长，例如 range(5, 0, -1)。只有后续操作确实需要一个可修改列表时，才有必要调用 list(range(...))。

排序以后，原来的顺序还要不要保留#

读取成绩时可能既要保留录入顺序，又要展示排名。这种情况下，可以生成另一份排序结果：

python
scores = [81, 92, 75]
ranking = sorted(scores, reverse=True)
print(scores)   # [81, 92, 75]
print(ranking)  # [92, 81, 75]

result = scores.sort()
print(scores)  # [75, 81, 92]
print(result)  # None

sorted 接收可迭代对象，返回新列表；列表的 sort 原地修改自身，返回 None。写成 scores = scores.sort()，最后变量绑定的就不再是列表。许多原地修改方法返回 None，正是为了让这种副作用与“产生一个新值”的操作有所区别。

如果还要先筛出不低于80分的成绩，可以这样组织结果：

python
passed = [score for score in scores if score >= 80]

这会保留原列表，另建一个符合条件的列表。后面要对结果排序，就继续对 passed 操作。沿着数据接下来要做什么选择容器和方法，通常比先背一串API更容易记住它们。
