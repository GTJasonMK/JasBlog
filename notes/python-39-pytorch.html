Python 39：PyTorch：张量、梯度和训练循环怎么连起来

目录

训练代码里连续出现 loss.backward() 和 optimizer.step()，很容易把它们一起理解成“模型学了一次”。拆开看就会发现，前者回答参数应该往哪个方向调整，后者才真正修改参数。理解这个区别，比先背一套训练循环更有用。

PyTorch用张量表示数值。张量可以是标量、向量、矩阵，也可以有更多维度；shape 表示每个维度多长，dtype 决定元素如何表示，device 决定数据放在CPU还是其他计算设备上。它和NumPy数组看起来相似，但还可以记录计算过程并求导。

先算一份能核对的梯度#

安装 torch 后运行下面的例子。四个数先各自平方，再取均值：

python
import torch

x = torch.tensor([[1.0, 2.0], [3.0, 4.0]], requires_grad=True)
loss = (x * x).mean()
loss.backward()
print(x.grad)

损失是 (1 + 4 + 9 + 16) / 4 = 7.5。对其中一个元素求导，得到 2x / 4，所以梯度依次是0.5、1、1.5、2。这个结果会出现在 x.grad，而 x 本身仍然是原来的四个数。

requires_grad=True 让PyTorch在相关运算中建立计算图。backward 沿图应用链式法则，把最终损失对各参数的导数算出来。模型层数很多时，不需要手工展开所有导数，但仍然必须选对损失：损失衡量什么，更新就朝降低什么的方向进行。

让参数真的动一下#

再把问题缩到只有一个权重。输入是1，希望预测结果是2，当前权重为0：

python
import torch

weight = torch.nn.Parameter(torch.tensor(0.0))
optimizer = torch.optim.SGD([weight], lr=0.1)
optimizer.zero_grad()
prediction = weight * 1.0
loss = (prediction - 2.0) ** 2
loss.backward()
print(weight.item(), weight.grad.item())  # 0.0 -4.0
optimizer.step()
print(weight.item())  # 约0.4

这次梯度是 2 × (0 - 2) = -4，SGD按“参数减去学习率乘梯度”更新，得到 0 - 0.1 × (-4) = 0.4。预测从0向目标2靠近了一步，却还没到2。学习率决定这一步多大，过大可能越过合适位置，过小则需要更多迭代。

梯度默认会累积，因此通常在每个优化步前清零，再前向计算、求损失、反向传播、更新。某些大模型训练会有意跨多个小批次累积梯度，但那需要明确的缩放与更新频率，不能把忘记清零当作相同行为。

一批数据怎样进入网络#

Dataset 负责按索引提供样本，DataLoader 把样本组成批次，可以在训练时打乱顺序。全连接层常接收 (批大小, 特征数)；二维卷积常接收 (批大小, 通道数, 高, 宽)。批大小变化通常没有问题，特征维度变化却可能使矩阵乘法无法进行。

有时更麻烦：形状不同却可以广播，程序照样运行，损失却比较了不该比较的元素。排查时沿输入、每层输出和损失两端查看shape，不能只看有没有报错。分类标签通常是整数类别编号，特征则常用浮点；模型参数与输入还需要放到匹配的设备上。

全连接网络处理固定长度特征，卷积通过局部计算与权重共享利用图像空间关系，注意力模型则用于学习位置间的关联。结构应对应数据里的关系，任意把表格凑成图片形状，并不会凭空产生图像的局部语义。

eval和no_grad为什么都要写#

model.train() 与 model.eval() 切换Dropout、BatchNorm等层的行为；torch.no_grad() 关闭当前计算的梯度记录，减少评估时不需要的计算图。调用eval不会自动关闭求导，关闭求导也不会自动把模型切到评估模式，二者承担不同职责。

训练集用于更新参数，验证集用于选择结构、学习率和训练轮数，测试集留作最后评估。若训练损失继续下降而验证表现变差，可能已经开始贴合训练样本中的偶然细节。下一篇用内置手写数字数据走完这个过程，并核对保存前后预测能否一致。
