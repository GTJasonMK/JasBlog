TypeScript 57：构建与部署：把本机能跑变成可重复交付

TypeScript全栈整合与发布

本机能跑，有时依赖的是没提交的全局工具、旧迁移与环境变量。换一个干净目录，从锁文件和README重新启动，才能发现真正缺失的步骤。交付的对象不仅是源码，还有可复现的运行条件。

生产构建使用锁定依赖；构建前执行类型检查和测试。部署时提供数据库连接、会话密钥等环境变量，执行已审核迁移，再启动 API 和静态前端。Docker Compose 可用于本地启动 PostgreSQL 和应用依赖；VPS 通过反向代理提供 HTTPS。

发布前确认健康检查、日志、数据库备份和恢复方式。不要把 .env、数据库快照或密钥提交到 Git。

前端产物由静态服务器提供，API运行构建后的JavaScript，共享包的产物与公开入口也要可用。生产不用Vite开发服务器，数据库迁移不由浏览器或每次请求临时触发。每项命令在哪个包目录执行，在README里写清楚。

本地 PostgreSQL：Compose 示例#

将以下内容保存为仓库根目录的 compose.yaml。数据库容器只从根目录的 .env.db 读取密码；不要提交 .env.db：

yaml
services:
  db:
    image: postgres:16
    restart: unless-stopped
    env_file:
      - .env.db
    environment:
      POSTGRES_DB: task_app
      POSTGRES_USER: task_app
    ports:
      - "127.0.0.1:5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U task_app -d task_app"]
      interval: 5s
      timeout: 3s
      retries: 10

volumes:
  postgres-data:

在根目录的 .env.db 中设置仅供本地开发的 POSTGRES_PASSWORD；在 apps/api/.env 中设置 DATABASE_URL，连接串中的密码必须与容器密码相同，特殊字符要按 URL 规则编码。确保这两个文件在 .gitignore 中，再从仓库根目录启动数据库：

sh
docker compose up -d db

然后进入 apps/api，首次运行时创建初始迁移并启动 API：

sh
cd apps/api
npx prisma migrate dev --name init
npm run dev

后续 Schema 改动使用描述该改动的迁移名。API 进程也必须能读取 DATABASE_URL。生产环境不得使用示例密码或向公网开放数据库端口。

apps/api 的开发脚本必须显式加载 apps/api/.env，或由 shell 注入 DATABASE_URL；不要假设 Node.js 会自动读取 .env。

Compose示例只启动本地数据库，不包含API完整部署。容器首次初始化读取数据库用户与密码，已有持久卷不会因为改环境变量自动重设密码；遇到认证失败先核对卷与实际账号，不能盲目删除卷丢掉数据。健康检查也只表示数据库能接受连接，不证明应用Schema与迁移已就绪。

发布顺序#

  1. CI 安装锁定依赖，运行类型检查、Lint、测试和生产构建。
  2. 准备HTTPS、生产配置、数据库和持久化会话存储，确认数据库只对应用网络开放，并核对可恢复备份。
  3. 上传已经验证的API与前端制品，按兼容顺序在API package目录运行npx prisma migrate deploy；migrate dev只用于本地开发。
  4. 启动新版本，检查健康与受控业务请求，再切换流量；反向代理将/api送到API，前端页面与静态资源按各自规则处理。
  5. 验证备份可恢复，并记录回滚应用版本与数据库迁移的方案。

生产迁移应采用向前兼容的 expand/contract 流程：先增加兼容字段并发布读写兼容版本，再迁移数据，最后移除旧字段。只依赖“回滚应用镜像”无法撤销破坏性数据库变更。

新旧浏览器脚本可能短暂共存，接口不能假定所有客户端同时更新。深层路由刷新与API404分别检查，避免代理把错误接口也返回index.html，导致客户端看到HTML解析错误。

发布记录关联源码提交、制品身份、迁移版本与配置版本。异常时先确认影响与最近变化，再决定停止切流或回滚兼容应用；涉及数据变化则按恢复计划处理，不能只看服务重新变绿就认定所有任务与会话都正确。

项目验收#

  • 注册、登录、退出和当前用户查询可用。
  • 未登录和越权访问均被 API 拒绝。
  • 任务 CRUD、校验、空状态和失败反馈完整。
  • 单元、API、端到端测试和生产构建通过。
  • README 写明安装、环境变量、数据库迁移、启动和部署流程。
