一份任务列表长度会变化，但每项都是任务；一个坐标则是两个位置各有含义的值。都写成普通数组，调用方就不知道第二项一定存在、它代表什么。类型应保留数据结构里真正有用的关系。

数组元素使用同一元素类型，元组表示位置和长度都重要的小集合。对象类型可表达必需、可选、只读字段和索引签名。

~~~ts
type Task = {
  id: string;
  title: string;
  description?: string;
  readonly createdAt: Date;
};

const pair: [string, number] = ["page", 1];
const tasks: Task[] = [];
~~~

可选属性读取后可能是 undefined。readonly 限制通过该类型写入，不会在运行时冻结对象。

Task[]允许任意数量任务，pair元组则在已知位置分别对应string和number。可变元组仍有数组方法，若需要固定只读位置，用readonly元组更清楚。类型不检查外部JSON长度，所以网络收到的二元素数组仍要在解析时确认。

description带问号，读取时得到string或undefined；空字符串与省略字段仍不同。exactOptionalPropertyTypes启用后，还会进一步区分可选字段省略与显式赋undefined。输入与PATCH语义需要这种区别时，类型配置和运行时解析应保持一致。

createdAt字段readonly，不允许通过这份类型替换成另一个Date，但Date本身仍可调用修改方法。只读通常只限制当前静态访问视图，不是深冻结，也不证明其他别名不会修改对象。

## 静态只读不会冻结对象

- 把字段标成可选，意味着调用方必须考虑它可能不存在。
- 索引签名会放宽对象边界，只在字段确实动态时使用。
- TypeScript 对象类型是结构化的：形状兼容即可赋值。

结构化类型只要求需要的字段，不一定禁止额外字段。新鲜对象字面量有额外属性检查，已经存在的更大对象却可能兼容较小接口；因此把一个数据库对象赋给公开响应类型，并不会自动删除密码字段。真正输出时仍要构造白名单对象。

索引签名适合字段名确实动态的字典，不适合用来消除拼错title后的错误。数组下标也可能越界，noUncheckedIndexedAccess让很多下标读取包含undefined；无论配置是否提醒，运行时都需要处理空数组与未命中。
