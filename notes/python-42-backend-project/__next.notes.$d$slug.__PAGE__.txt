内存列表也能做任务增删改查，但服务一重启就没了，多进程之间也不会共享同一份列表。这个例子把任务放进SQLite文件，重点看一条HTTP请求如何变成一次数据库操作。

每项任务有编号、标题和完成状态，没有用户归属和登录功能，因此只作为本地学习API。数据层用SQLModel连接SQLAlchemy与Pydantic，SQLite驱动为同步调用，路由使用普通 `def`。

## 先看模型之间的区别

`TaskCreate` 描述允许创建的字段，不让调用者指定数据库编号；`Task` 对应数据库表；`TaskUpdate` 描述局部更新。它们共享标题与完成状态的定义，但输入职责不同，不能把数据库整行直接当作所有请求的合同。

PATCH还要区分“不修改”和“修改成某个值”。省略 `done` 应保留原状态，传 `false` 应把它设为未完成；本例不允许把标题或状态改成null，后面的更新逻辑会显式拒绝。

安装依赖：`python -m pip install fastapi uvicorn sqlmodel pytest httpx`。

把下面保存为 `app.py`：

```python
import os

from fastapi import Depends, FastAPI, HTTPException, Response
from sqlmodel import Field, Session, SQLModel, create_engine, select

database_url = os.environ.get("DATABASE_URL", "sqlite:///tasks.db")
connect_args = {"check_same_thread": False} if database_url.startswith("sqlite") else {}
engine = create_engine(database_url, connect_args=connect_args)


class TaskBase(SQLModel):
    title: str = Field(min_length=1, max_length=120)
    done: bool = False


class Task(TaskBase, table=True):
    id: int | None = Field(default=None, primary_key=True)


class TaskCreate(TaskBase):
    pass


class TaskUpdate(SQLModel):
    title: str | None = Field(default=None, min_length=1, max_length=120)
    done: bool | None = None


def get_session():
    with Session(engine) as session:
        yield session


app = FastAPI()


@app.post("/tasks", response_model=Task, status_code=201)
def create_task(data: TaskCreate, session: Session = Depends(get_session)):
    task = Task(title=data.title, done=data.done)
    session.add(task)
    session.commit()
    session.refresh(task)
    return task


@app.get("/tasks", response_model=list[Task])
def list_tasks(session: Session = Depends(get_session)):
    return session.exec(select(Task).order_by(Task.id)).all()


@app.patch("/tasks/{task_id}", response_model=Task)
def update_task(
    task_id: int, data: TaskUpdate, session: Session = Depends(get_session)
):
    task = session.get(Task, task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="任务不存在")
    changes = data.model_dump(exclude_unset=True)
    if not changes or any(value is None for value in changes.values()):
        raise HTTPException(status_code=422, detail="至少提供一个非空更新字段")
    for key, value in changes.items():
        setattr(task, key, value)
    session.add(task)
    session.commit()
    session.refresh(task)
    return task


@app.delete("/tasks/{task_id}", status_code=204)
def delete_task(task_id: int, session: Session = Depends(get_session)):
    task = session.get(Task, task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="任务不存在")
    session.delete(task)
    session.commit()
    return Response(status_code=204)
```

首次本地运行前，创建 `init_db.py`：

```python
from sqlmodel import SQLModel
from app import engine

SQLModel.metadata.create_all(engine)
```

执行 `python init_db.py` 后，再运行 `uvicorn app:app --reload`，用 `/docs` 创建任务并验证 CRUD。`--reload` 只用于开发；生产项目通过 Alembic 迁移建表，不在服务启动时自动修改数据库结构。

## 沿着创建与更新走一遍

`get_session` 为一次请求创建会话，并在请求结束后关闭。会话跟踪对象变化；`add` 把新任务加入工作单元，`commit` 提交事务，`refresh` 再读取数据库生成的编号等值。因此返回的任务能带上实际主键，而不是尚未持久化的临时状态。

更新先按编号找记录，不存在就返回404。`model_dump(exclude_unset=True)` 只取调用方实际提供的字段，因此 `{ "done": false }` 会被保留，不能写成“值为真才更新”。空对象与显式null都返回422，成功后再统一提交。若提交失败，会话退出时释放资源，异常不会被伪装成更新成功。

SQLite的 `check_same_thread=False` 允许驱动连接用于这里的线程执行方式，不代表同一个Session可以任意跨线程共享，更不代表SQLite获得无限并发写入能力。每个请求仍独立使用会话，文件数据库的写锁行为也仍然存在。

列表查询按编号排序，方便结果稳定可查；当前没有分页，适合少量学习数据。扩展到真实列表时，应同时定义上限、排序和游标，不能把无界查询当作长期接口。

## 部署与交付

1. **管理配置：**默认 SQLite URL 可用于本地学习。部署 PostgreSQL 时，通过 `DATABASE_URL` 设置连接串，并安装对应数据库驱动；不要把连接密码提交到仓库。
2. **管理迁移：**安装 Alembic 后运行 `alembic init migrations`；在 `migrations/env.py` 里导入 `SQLModel` 和任务模型，把 `target_metadata` 指向 `SQLModel.metadata`，并从 `DATABASE_URL` 设置 Alembic 的连接地址；运行 `alembic revision --autogenerate -m "create tasks"`，检查生成的 SQL 后再运行 `alembic upgrade head`。不要在生产启动时自动调用 `create_all`。
3. **锁定依赖：**依赖至少包括 FastAPI、Uvicorn、SQLModel、Alembic 和目标数据库驱动；在已验证环境中记录 Python 与依赖版本，再生成部署使用的锁文件或带精确版本的依赖清单。
4. **构建容器：**把下列内容保存为 `Dockerfile`，并提供锁定后的 `requirements.txt`：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN python -m pip install --no-cache-dir -r requirements.txt
COPY app.py .
COPY alembic.ini .
COPY migrations ./migrations
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

5. **运行服务：**容器或服务器使用不带 `--reload` 的 ASGI 服务；生产环境还需 TLS 反向代理、健康检查、日志、数据库备份及访问控制。认证应使用成熟的框架方案，并对每个资源检查授权。

## 用请求测试这份合同

在项目根目录创建 `test_app.py`，用临时 SQLite 文件隔离测试数据：

```python
import app as task_app
from fastapi.testclient import TestClient
from sqlmodel import SQLModel, create_engine


def test_task_crud(tmp_path, monkeypatch):
    test_engine = create_engine(
        f"sqlite:///{tmp_path / 'test.db'}",
        connect_args={"check_same_thread": False},
    )
    monkeypatch.setattr(task_app, "engine", test_engine)
    try:
        SQLModel.metadata.create_all(test_engine)
        with TestClient(task_app.app) as client:
            created = client.post("/tasks", json={"title": "学习 Python"})
            assert created.status_code == 201
            task_id = created.json()["id"]

            updated = client.patch(f"/tasks/{task_id}", json={"done": True})
            assert updated.status_code == 200
            assert updated.json()["done"] is True
            reset = client.patch(f"/tasks/{task_id}", json={"done": False})
            assert reset.json()["done"] is False
            assert client.patch(f"/tasks/{task_id}", json={}).status_code == 422
            assert client.patch(f"/tasks/{task_id}", json={"title": None}).status_code == 422
            assert client.get("/tasks").json()[0]["title"] == "学习 Python"
            assert client.delete(f"/tasks/{task_id}").status_code == 204
            assert client.patch("/tasks/999", json={"done": True}).status_code == 404
            assert client.post("/tasks", json={"title": ""}).status_code == 422
    finally:
        test_engine.dispose()
```

运行 `python -m pytest`。临时数据库与开发文件分开；测试不只检查函数返回值，还通过TestClient完成请求解析、路由、数据库提交与响应序列化。完成状态改回false、空PATCH与null也被覆盖，这些恰好是局部更新容易混淆的边界。

## 本地演示和真实用户服务的边界

`create_all` 适合初始化空的本地演示库，不会按模型变化自动完成已有表的迁移。部署步骤需要单独准备与检查迁移文件，Dockerfile中的路径也必须实际存在，不能只复制这份API脚本就声称已经完成部署。

真实用户服务还需要任务所属关系和资源授权。仅仅给路由加一个“已登录”检查，仍可能让用户按编号改到别人的任务；查询与修改必须把当前身份和目标资源关联起来。先确认这个边界，再扩展多用户功能，能够避免把演示里的全局任务表误当作安全的产品行为。
