本地函数可以直接调用 `greet("Ada")`，另一台电脑却不能凭一个函数名找到它。后端需要先约定通信方式：请求发到哪个地址，用什么方法，参数放在哪里，失败又怎样告诉调用方。HTTP接口就是把这些约定放到网络边界上。

一次请求通常包含方法、路径、查询参数、请求头和可选的请求体。响应包含状态码、响应头和内容。JSON只规定内容的表示语法，没有规定里面一定有合法姓名，更没有证明请求来自谁。

## 从JSON进入函数

把下面保存为 `app.py`。FastAPI根据Pydantic模型读取和检查请求体，校验通过才调用路由函数：

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class Greeting(BaseModel):
    name: str = Field(min_length=1, max_length=80)


@app.post("/greet")
def greet(body: Greeting) -> dict[str, str]:
    return {"message": f"你好，{body.name}"}
```

安装 `python -m pip install fastapi uvicorn`，运行 `uvicorn app:app --reload`，打开 `http://127.0.0.1:8000/docs`。提交 `{"name":"Ada"}`，应得到 `{"message":"你好，Ada"}`；提交空字符串，应得到422校验错误。路由函数不必再手写一次JSON解析和相同长度检查。

不过，一个空格也满足长度至少为1。若业务要求去掉两端空白后仍有名字，应显式加入规范化与校验，不能从 `min_length=1` 推出这个结论。Pydantic还可能按类型规则转换部分输入；要求严格类型时也应明确配置。边界规则具体到哪一步，测试就覆盖到哪一步。

`--reload` 用于本地修改后重启，不用于正式服务。运行命令里的前一个 `app` 是文件模块名，后一个是模块中创建的ASGI应用对象；改了文件名，也要对应修改入口。

## HTTP方法不替你执行规则

读取任务通常用 `GET /tasks/12`，创建用 `POST /tasks`，局部修改用 `PATCH /tasks/12`，删除用 `DELETE /tasks/12`。创建成功返回201可以表达产生了新资源；没有这个任务返回404，输入不合法可以返回422，未认证与无权访问则要根据接口合同区分。

方法和状态码帮助客户端理解语义，却不会自动实现它们。重复POST会不会创建两份订单，需要业务幂等规则；同一任务能否被别人删除，需要资源授权。只检查任务编号是整数，无法回答这两个问题。

## HTTP 与关系数据库基础

当任务需要跨重启保留，就要把状态放到持久存储。关系数据库用表保存记录，主键标识一行，外键表达关联。例如任务有所属用户时，可以连接两张表读取：

关系数据库用表保存记录：主键唯一标识一行，外键连接另一张表。常见 SQL 读法：

```sql
SELECT tasks.id, tasks.title, users.name
FROM tasks
JOIN users ON tasks.owner_id = users.id
WHERE tasks.done = ?;
```

这里的 `?` 是参数占位符，具体写法由驱动决定。参数值单独传给驱动，不能把外部输入拼进SQL。查询能返回用户名字，不等于已经验证当前请求有权访问这个用户的数据；权限条件仍须进入相应查询或业务检查。

一次操作如果要同时扣库存与创建订单，事务可以使这组数据库写入一起提交或回滚。ORM帮助表达查询和映射对象，不会让两次独立提交自动变成事务，也不会自动避免并发超卖。索引、约束和隔离仍然决定真实行为。

## 服务安全与框架选择

认证确认身份，授权判断该身份能否操作目标资源。密码使用专门的密码哈希方案，密钥从环境或密钥管理服务读取；异常响应保留可用信息，同时避免把数据库连接串或内部堆栈直接交给客户端。

同步数据库驱动可以配普通 `def` 路由，FastAPI会在线程池中执行它。`async def` 适合等待异步I/O；直接在其中运行阻塞驱动，会阻塞事件循环，而不是自动获得更多并发。选择函数形式应跟随调用链，不能只看关键字更像哪种风格。

FastAPI适合以API为主要边界的服务；需要内置管理后台、完整用户与Web功能时，可以考虑Django；Flask则给出更轻的核心。框架负责的内容不同，业务规则仍然需要明确。下一篇用任务API把请求模型、会话、提交与测试实际接起来。
