环境变量PORT是文本，直接加1可能得到字符串拼接，`Boolean("false")` 又会得到true。配置不会因为名字像数字或开关就自动具有对应类型。长期服务先在入口把外部值解析成明确配置，再交给业务。

Node.js 用 V8 执行 JavaScript，并提供文件、环境变量、网络等服务端 API。服务端进程启动后持续监听请求，收到终止信号时应释放资源。不要在业务模块里散落环境变量读取。

TypeScript 项目可由开发工具执行 TS，也可先构建 JS 再运行；开发和生产应使用清晰一致的脚本。路径、文件系统和进程 API 仅在 Node 环境可用。

例如端口可以要求完整十进制文本，禁止parseInt把80abc只读成80：

~~~ts
function readPort(value: string | undefined): number {
  if (value === undefined || !/^\d+$/.test(value)) {
    throw new Error("PORT必须是十进制整数文本");
  }
  const port = Number(value);
  if (!Number.isInteger(port) || port < 1 || port > 65535) {
    throw new Error("PORT必须在1到65535之间");
  }
  return port;
}
~~~

这是选择不提供默认端口的合同；如果项目允许省略，可以在配置层声明固定默认值，但非法提供值仍应报错。错误说明变量名与原因，不打印敏感原值。

Node的事件循环处理异步完成与回调，阻塞同步文件操作或大计算会拖住其他请求。服务端async函数也不会把CPU工作自动分配到线程；需要按实际瓶颈考虑流、Worker或独立任务，并控制资源。

收到 SIGTERM 时停止接受新请求，等待正在处理的请求结束，并关闭 HTTP server 和 Prisma 连接。设置有限的关闭超时；超时后让进程管理器回收进程，避免部署时旧实例无限挂起。

应用模块可以导出Express app供测试，真正监听端口放在入口。这样导入路由不会意外占端口，配置和依赖也能由入口显式注入。启动第三项依赖失败时，要释放前面已经创建的资源，不能只有完整成功时才有清理路径。

未捕获的严重异常后继续假装健康，可能保留不一致状态。记录必要原因、停止接流量并受控退出，让平台发现失败；不能用全局catch把所有错误吞成成功。正常信号退出与故障退出也应在结果里区分。

## 运行环境和配置值都要显式确认

- 浏览器对象如 window、document 在 Node 中不存在。
- 环境变量值都是字符串，不能直接假定为数字或布尔值。
- 进程异常退出时，应保留错误并让运行平台发现失败。
