有五笔订单和一张客户地区表，要回答两个问题：各地区收入分别多少，1月与2月收入各是多少。这个任务足够小，可以先手工核对总额，再检查代码的每一步有没有改变统计口径。

这里每行表示一笔订单，同一币种下收入等于数量乘以单价，没有退货、折扣和税费。数据直接嵌在程序中，安装依赖后可以离线运行；换成自己的CSV时，必须先核对这些前提。

安装依赖：`python -m pip install numpy pandas matplotlib`。

把下面内容保存为一个分析脚本。先读入两张表，再检查订单编号和缺失值，随后连接地区并汇总：

```python
from io import StringIO
import pandas as pd
import matplotlib.pyplot as plt

orders_csv = """order_id,date,customer_id,product,quantity,unit_price
O1,2025-01-03,C1,Book,2,12.5
O2,2025-01-04,C2,Pen,5,2.0
O3,2025-01-08,C1,Pen,3,2.0
O4,2025-02-02,C2,Book,1,12.5
O5,2025-02-09,C3,Notebook,2,4.0
"""
customers_csv = """customer_id,region
C1,North
C2,South
C3,North
"""

orders = pd.read_csv(StringIO(orders_csv), parse_dates=["date"])
customers = pd.read_csv(StringIO(customers_csv))
if orders["order_id"].duplicated().any() or orders.isna().any().any():
    raise ValueError("订单包含重复编号或缺失值")

df = orders.merge(customers, on="customer_id", how="left", validate="many_to_one")
if df["region"].isna().any():
    raise ValueError("存在未登记地区的客户")
df["revenue"] = df["quantity"] * df["unit_price"]
summary = df.groupby("region", as_index=False)["revenue"].sum()
monthly = df.set_index("date").resample("MS")["revenue"].sum()
by_region_product = df.pivot_table(
    index="region", columns="product", values="revenue", aggfunc="sum", fill_value=0
)
print(summary)
print(monthly)
summary.to_csv("region_summary.csv", index=False)
by_region_product.to_csv("region_by_product.csv")

summary.plot(x="region", y="revenue", kind="bar", legend=False)
plt.ylabel("Revenue")
plt.tight_layout()
plt.savefig("sales_by_region.png", dpi=150)
```

## 先手算一遍，再对照分组结果

O1收入25，O2收入10，O3收入6，O4收入12.5，O5收入8，总计61.5。C1与C3属于North，合计39；C2属于South，合计22.5。1月包含O1到O3，合计41；2月包含O4和O5，合计20.5。

这些值来自输入本身，不是模型预测或性能指标。程序输出应该与它们一致，地区汇总的总和与月份汇总的总和也应重新等于61.5。若连接后多了一行，或者某笔订单没有地区而在分组时被省掉，这种总量核对就有机会发现问题。

真实项目不一定能手算所有记录，但仍然可以选择可靠的基线、边界样本和勾稽关系验证。图表已经生成，只能证明绘图步骤完成，不能证明前面的订单没有被重复计算。

## 为什么连接要声明多对一

订单可以重复使用客户编号，客户地区表中的客户编号却应该唯一，所以使用 `validate="many_to_one"`。若同一个客户意外有两条地区记录，连接会明确失败，不让同一笔收入进入两个分组。

左连接保留所有订单，随后检查 `region` 是否缺失，避免未登记客户的订单在分组时悄悄消失。输入检查分别维护订单唯一性、必要字段和客户匹配，它们不是一个 `dropna` 就能替代的动作。

当前脚本主要服务于这份已知样例，只检查重复和缺失还不足以接受任意外部数据。负数量、非法价格、无效日期和字符串混入数值列，都需要在扩大输入范围前明确验证。演示中的数值适合展示聚合；严格财务结算则应采用明确的金额表示、币种和舍入规则。

## 输出表格与图片，各自承担什么用途

`summary` 适合查看地区总额，透视表适合比较地区与商品的组合，`monthly` 体现月份变化。它们不是互相替代的三份装饰，而是在相同订单口径上回答不同问题。

输出CSV时，地区已经是普通列，因此使用 `index=False`；透视表中的地区是有含义的行索引，输出时则保留。条形图用于比较地区总收入，纵轴注明Revenue，实际报告还需要明确币种、期间和口径。

同样的输入重复运行会重新生成同样内容的汇总文件，当前文件名存在时会覆盖。正式交付要明确输出目录、覆盖策略和任务标识，图片也不能作为唯一可追查的数据来源。脚本或Notebook应随数据来源、依赖版本和清理规则一起保存。

最后按商品名精确取出Book订单，忽略大小写，检查细节能否对应回输入：

```python
books = df["product"].str.casefold().eq("book")
print(df.loc[books, ["order_id", "product", "revenue"]])
```

`books` 是布尔掩码，选中O1和O4，两笔合计37.5。如果使用包含子串的contains，Notebook也会被选中，总额变成45.5；筛选方法必须对应实际类别含义。地区差异在这份数据里只是观测结果，没有随机实验或其他识别条件，不能据此认定某地区导致更高消费。分析完整到可以复查输入、转换、结果和适用解释，才算交付了一份可以继续使用的结论。
