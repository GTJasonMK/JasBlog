脚本刚开始只有几行时，直接修改变量就能换输入。等到要让另一个人使用，或者放进定时任务，输入应该从命令行进入，而不是要求每次打开代码改值。命令行参数、子进程和HTTP，都是程序与外部协作的方式，只是协作对象和失败规则不同。

## 把命令写成一个可说明的接口

将下面内容保存为 `greet.py`：

```python
import argparse

def main(argv=None):
    parser = argparse.ArgumentParser(description="按指定次数输出问候")
    parser.add_argument("name", help="称呼")
    parser.add_argument("--repeat", type=int, default=1)
    args = parser.parse_args(argv)
    if not 1 <= args.repeat <= 10:
        parser.error("--repeat 必须在1到10之间")
    for _ in range(args.repeat):
        print(f"你好，{args.name}")

if __name__ == "__main__":
    main()
```

执行 `python greet.py Ada --repeat 2` 会输出两次问候，`python greet.py --help` 会显示使用说明。`argparse` 处理参数位置、名称和基本类型转换，程序再检查次数范围。`type=int` 不代表负数也可以接受，业务条件仍需补上。

`main(argv=None)` 默认读取真正的命令行，测试时也能传入 `main(["Ada", "--repeat", "2"])`。输入解析独立出来后，后面的处理不必到处读取全局 `sys.argv`。

## 子进程是另一个执行结果，不是一次普通函数调用

调用系统中的其他程序，可以使用 `subprocess.run`。下面启动同一个Python解释器做一个最小计算：

```python
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "-c", "print(2 + 3)"],
    check=True,
    capture_output=True,
    text=True,
    encoding="utf-8",
    timeout=5,
)
print(result.stdout.strip())  # 5
```

参数列表把程序和各个参数分开，默认不经过shell解释。`check=True` 在退出码非零时抛出 `CalledProcessError`，`timeout` 则限制这次等待，不能只看“进程启动成功”就认为任务完成。错误信息也可能写在标准错误流，需要按目标工具的约定检查。

`capture_output=True` 会把输出收进内存，适合有边界的小输出。可能产生大量内容的任务，应使用文件或流式读取，避免因为抓取输出而耗尽内存。

外部输入不能直接拼进shell命令。即使不使用shell，某些程序仍会把以 `-` 开头的输入当成选项，所以也要根据目标程序规则区分选项和数据，必要时使用它支持的 `--`。参数列表解决shell解释问题，不会替目标程序完成全部输入校验。

## HTTP有三次不同的检查

网络请求需要分别确认：是否连接并得到响应，HTTP状态是否符合预期，响应内容是否符合业务结构。服务器返回404时，连接本身往往已经成功；返回200也可能带来错误字段。

下面使用第三方库HTTPX，先安装到当前项目环境：

```console
python -m pip install httpx
```

请求一个网页并检查HTTP状态，可以这样写：

```python
import httpx

response = httpx.get("https://example.com", timeout=10)
response.raise_for_status()
print(response.status_code)
```

这段例子只检查状态，不把网页HTML当作JSON解析。访问真实JSON接口时，还要对 `response.json()` 的结果检查字段和类型，具体方法见[数据格式](/notes/python-12-data-formats)。

为了单独验证这段边界处理，也可以用HTTPX的测试传输提供确定的响应，不连接真实网络：

```python
import httpx

def read_count(client):
    response = client.get("https://example.test/count")
    response.raise_for_status()
    data = response.json()
    if not isinstance(data, dict) or type(data.get("count")) is not int:
        raise ValueError("响应缺少整数count")
    return data["count"]

def respond(request):
    return httpx.Response(200, json={"count": 3})

transport = httpx.MockTransport(respond)
with httpx.Client(transport=transport, timeout=5) as client:
    print(read_count(client))  # 3
```

将响应改成500、改成无效JSON、或者把 `count` 改成字符串，会分别走到不同的失败处。这样能证明代码确实检查了每一层，而不必等外部服务器碰巧出错。

## 超时和重试也有范围

HTTPX可以分别控制连接、读取、写入和连接池等待的超时；单个超时值不应被理解为整个业务流程绝不会超过这个总时长。多次请求和重试还需要一个共同的时间预算。

网络错误、HTTP失败、字段校验失败，应该保留足够信息供调用者判断。重试只针对确有机会恢复的情况，还要考虑重复执行的后果；一次创建订单请求超时，不足以证明订单没有创建成功。

程序需要鉴权时，凭证从环境或项目既有安全配置读取，不写进示例地址，也不把完整请求头记录到日志。多次访问同一服务时，客户端对象可以复用连接；用 `with` 明确关闭客户端，让连接生命周期与当前任务一致。

这三种协作方式都应把外部结果转成清楚的成功或失败，再交给内部逻辑。传入的数据是哪一种、等待多久、怎样确认完成，每个接口都需要自己的答案。
