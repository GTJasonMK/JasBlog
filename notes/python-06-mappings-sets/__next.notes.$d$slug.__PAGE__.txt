有一个用户列表，要根据用户编号取出邮箱，可以从头循环，找到编号相等的那条记录再返回。如果每次查询都这样做，数据越多，平均需要检查的项也越多。若一开始就把编号与资料组织成对应关系，查询会直接得多。

字典 `dict` 表达的就是这种键到值的映射。同一个字典里，一个键最多对应一个当前值；再给相同的键赋值，会替换原来的值。

```python
users = {
    101: {"name": "Ada", "email": "ada@example.com"},
    102: {"name": "Lin", "email": "lin@example.com"},
}
print(users[101]["email"])  # ada@example.com
users[102]["email"] = "new@example.com"
```

适合字典的场景包括按ID查对象、按配置名称取参数、统计每个词出现几次。如果记录本身需要保留多个相同键的值，例如一个用户对应多个订单，就把值设计成列表或集合；字典不会自动保存被覆盖的历史值。

## 不存在的键和空值要分开

`users[999]` 会抛出 `KeyError`。当这个用户理应存在时，错误是有用的线索。若未找到本来就是正常分支，可以用 `users.get(999)` 获得 `None`，或者提供合适的默认值。

但 `get` 不会告诉你“键不存在”和“值恰好为 `None`”的区别：

```python
settings = {"timeout": None}
print(settings.get("timeout"))  # None
print(settings.get("missing"))  # None
print("timeout" in settings)   # True
print("missing" in settings)   # False
```

假如 `None` 表示明确关闭超时，缺失键表示采用系统默认值，这个差别就必须保留。可以先用 `in` 检查键是否存在；更复杂的接口也会使用专门的哨兵对象表示缺失。

要按键逐项处理，直接遍历字典；要同时拿到键和值，使用 `items()`。`keys()` 和 `values()` 提供相应视图，它们不是一份与字典脱离关系的历史快照。在遍历过程中增加或删除键，可能触发运行时错误，应先确定要修改的键，再进行修改。

把多个值归到同一组时，`setdefault` 可以在键缺失时放入初始值，并返回该键的值：

```python
groups = {}
for name, language in [("Ada", "Python"), ("Lin", "Go"), ("Mei", "Python")]:
    groups.setdefault(language, []).append(name)
print(groups["Python"])  # ['Ada', 'Mei']
```

这个写法适合小型分组。`setdefault` 的默认值表达式每次都会先求值，即使键已经存在，昂贵的对象也会被白建一次。若默认值需要复杂计算，就显式判断是否存在，或者选择合适的 `defaultdict` 工厂。

## 查询为什么快，又为什么不能用列表当键

字典通常借助哈希表定位键：先根据键计算哈希值，再在相应位置处理比较和冲突。因此按键查找的平均时间通常不随元素数线性增长，但这不代表每次操作都没有成本，哈希计算、冲突、扩容和内存占用都存在。

键必须可哈希，要求其哈希值在存活期间保持稳定，并与相等比较相容。列表会变化，不满足作为内置字典键的要求；整数、字符串和内容都可哈希的元组常可用作键。例如 `(year, month)` 可以表示一个月份，`([2026], 11)` 则因为包含列表而不可哈希。

集合 `set` 也利用哈希保存成员，要求类似，不过它只关心一个元素是否存在，不给元素再关联一个值。

## 去重之后，还需要原来的次序吗

```python
tags = ["python", "data", "python"]
unique_tags = set(tags)
print(len(unique_tags))         # 2
print("data" in unique_tags)   # True
```

集合适合成员判断、去重和不同群体之间的关系计算。它不保证按插入顺序遍历，所以别把 `list(set(tags))` 当作“保留第一次出现顺序”的去重方法。

如果要保留顺序，字典保留插入顺序这一语言保证就派上用场了：`list(dict.fromkeys(tags))` 得到 `['python', 'data']`。这仍要求各项可哈希。是否保序是选择方法的条件，不是事后再检查一下结果看着对不对。

两个用户的兴趣标签可以求交集：

```python
common = set(["python", "web"]) & set(["data", "python"])
print(common)  # {'python'}
```

`|` 求并集，`&` 求交集，`-` 求差集。例如当前角色拥有的权限减去接口要求的权限，回答的是“多了哪些”；要求的权限减去已有权限，回答的才是“还缺哪些”。写运算前先用一句话说清楚要的关系，方向就不容易写反。

若查询只发生一次、列表又很短，直接 `value in items` 通常已经足够。反复对大量元素做成员判断时，预先构造集合才可能省去重复扫描；集合也要占内存，建集合本身仍需遍历输入。把数据形状和操作频率一起考虑，才能判断这次转换值不值得。
