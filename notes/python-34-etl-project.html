Python 34：写一个订单 ETL 工具：读取、校验、转换和输出

收到两条订单，要交付一张订单总额表。表面上像是把JSON改写成CSV，实际上还要决定：一条记录长什么样，数量能否为小数，价格怎样表示，以及某条记录坏了以后是否仍然输出部分结果。

ETL对应提取、转换和加载。这里从文件读取记录是提取，字段检查和金额计算属于转换，写成CSV则是输出到下一种存储表示。这个例子选择整批验证通过才开始写出，便于区分“没有结果”与“有一份完整结果”。

输入#

创建 orders.json：

json
[
  {"order_id": "A-1", "customer": "Ada", "quantity": 2, "unit_price": "12.50"},
  {"order_id": "A-2", "customer": "Lin", "quantity": 1, "unit_price": "8.00"}
]

订单编号和客户名必须是非空文本，数量是正整数，单价表示有限且非负的十进制金额。示例把单价写成字符串，是为了保留十进制输入，而不是先由JSON解析成近似的二进制浮点数。所有金额假定使用同一币种和两位小数的输出规则。

这张表没有把多条相同订单号合并，也没有实现订单去重，调用者不应默认它具备那些行为。若业务需要唯一编号，应在转换阶段明确拒绝重复或定义聚合规则。

实现 etl.py#

先阅读 transform。它只接收解析后的记录并返回行数据，不负责找文件和写磁盘，因此可以独立验证转换规则：

python
import argparse
import csv
import json
import os
from decimal import Decimal, InvalidOperation
from pathlib import Path
from tempfile import NamedTemporaryFile


def transform(records):
    rows = []
    for record in records:
        try:
            order_id = record["order_id"]
            customer = record["customer"]
            quantity = record["quantity"]
            if not isinstance(order_id, str) or not isinstance(customer, str):
                raise TypeError("order_id 和 customer 必须是文本")
            if isinstance(quantity, bool) or not isinstance(quantity, int):
                raise TypeError("quantity 必须是整数")
            price = Decimal(str(record["unit_price"]))
        except (KeyError, TypeError, ValueError, InvalidOperation) as exc:
            raise ValueError(f"无效订单：{record!r}") from exc
        order_id = order_id.strip()
        customer = customer.strip()
        if not order_id or not customer or quantity <= 0 or not price.is_finite() or price < 0:
            raise ValueError(f"订单字段超出允许范围：{record!r}")
        rows.append({
            "order_id": order_id,
            "customer": customer,
            "quantity": quantity,
            "total": f"{price * quantity:.2f}",
        })
    return rows


def run(source, destination):
    if source.resolve() == destination.resolve() or (
        destination.exists() and source.samefile(destination)
    ):
        raise ValueError("输入和输出不能是同一个文件")
    records = json.loads(source.read_text(encoding="utf-8"))
    if not isinstance(records, list):
        raise ValueError("JSON 根节点必须是订单列表")
    rows = transform(records)
    destination.parent.mkdir(parents=True, exist_ok=True)
    temporary = None
    try:
        with NamedTemporaryFile(
            mode="w", newline="", encoding="utf-8", delete=False,
            dir=destination.parent, prefix=".orders-", suffix=".tmp",
        ) as file:
            temporary = Path(file.name)
            writer = csv.DictWriter(file, fieldnames=["order_id", "customer", "quantity", "total"])
            writer.writeheader()
            writer.writerows(rows)
        os.replace(temporary, destination)
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)


def main():
    parser = argparse.ArgumentParser(description="把订单 JSON 转成 CSV 汇总表")
    parser.add_argument("source", type=Path)
    parser.add_argument("destination", type=Path)
    args = parser.parse_args()
    run(args.source, args.destination)


if __name__ == "__main__":
    main()

运行 python etl.py orders.json output/orders.csv 后，A-1应得到 25.00，A-2应得到 8.00。CSV表头顺序由 fieldnames 明确给出，读取方不必根据字典碰巧的构造次序猜列含义。

沿着一条订单看失败发生在哪里#

先由 json.loads 确认语法合法，再由 run 确认根节点是列表。进入 transform 后，字段缺失、类型不合适和无法解析的价格都会被拒绝；随后再检查空文本、非正数量与无穷或负金额。

数量特别排除了布尔值，因为Python的 bool 是整数子类，仅用 isinstance(quantity, int) 会接纳 True。价格在比较大小之前先检查 is_finite()，避免把 NaN 或无穷大当成合法金额。

Decimal(str(...)) 允许转换一些已有的数值对象，但若上游已经把价格变成有误差的浮点数，这一步无法证明最初金额已无损恢复。因此输入合同最好坚持使用十进制字符串。示例按两位小数格式化，实际业务还需要明确最大位数、精度上下文和舍入规则，不能仅凭一个格式化操作决定税务或结算政策。

异常在示例中包含坏记录，方便离线排查。处理真实客户数据时，应改为记录订单位置或可公开标识，不把整条个人信息和金额内容无差别输出到日志。保留错误原因链，仍然可以追踪是字段访问还是数值转换失败。

最小测试#

python
from decimal import Decimal
from etl import transform


def test_transform_calculates_total():
    rows = transform([{
        "order_id": "A-1", "customer": "Ada", "quantity": 2, "unit_price": "12.50"
    }])
    assert rows[0]["total"] == "25.00"

**验收：**正常输入生成正确 CSV；缺字段、负数量、非列表 JSON 明确失败；测试可独立运行。

覆盖策略和数值边界要提前确定#

当前 run 会先构造完整行列表，再打开目标文件。因此输入校验失败时，不会因为提前打开 w 模式而截断目标文件。相同输入重复运行，通常会产生同样的CSV，不会不断追加同一批订单。

代码还会拒绝输入与输出指向同一个文件，并在目标目录写临时文件，完整写入并关闭后再替换目标。这样生成CSV的过程失败时，旧目标不会先被截断；临时文件也会清理。这里的同目录替换不等于已经实现断电持久性、并发写入版本检查或目标原权限保留，进一步交付时仍应根据环境补齐要求。

文件规模很大时，全部载入JSON和中间结果也会占内存。逐行输入格式与流式输出可以降低存储需求，却会让“后面一条坏了，前面已经写出”成为新的问题。这种改造必须同时定义失败和恢复规则，不能只把列表换成生成器就宣称等价。

加一个计算字段，规则会怎样变化#

若演示中固定税率为5%，可在 transform 中用 price * quantity * Decimal("1.05") 计算含税金额，再把新字段加入CSV列定义。公式、输出结构和测试都要一起调整，漏掉 fieldnames 就不能得到完整交付。

真实税率可能随商品、地区与时间变化，需要显式输入和适用规则。这也说明ETL的核心不是把字段从一处搬到另一处，而是让每项转换的含义、前提和失败后果都能追查。
