## 旧版本什么时候能回收

MVCC 更新和删除会留下旧版本。只有没有相关快照需要它们时，VACUUM 才能回收并使空间供后续写入复用。长事务、未结束的复制需求等可能延迟清理，持续产生旧版本后表和索引会膨胀。

普通VACUUM主要让不再需要的版本空间可供复用，后续写入不必一味扩文件。VACUUM FULL才通过重写整理紧凑文件，付出强锁与额外空间；磁盘已经很紧时，直接重写甚至可能没有足够临时容量。两种动作按目标选，不把FULL当更彻底的日常按钮。

`ANALYZE` 更新优化器统计，`VACUUM` 清理旧版本并维护可见性等信息，两者作用不同。autovacuum 负责自动维护，也承担防止事务 ID 回卷的关键任务，不要为了降低短期 I/O 直接关闭。

```sql
SELECT relname, n_live_tup, n_dead_tup,
       last_autovacuum, last_autoanalyze
FROM pg_stat_user_tables ORDER BY n_dead_tup DESC;

SELECT datname, age(datfrozenxid) AS xid_age FROM pg_database;
SELECT pid, now() - xact_start AS age, state, backend_xmin
FROM pg_stat_activity WHERE xact_start IS NOT NULL
ORDER BY xact_start;
```

`n_dead_tup` 是估计值，不是精确膨胀率。判断空间问题时还要结合关系大小、写入速率、长事务、维护进度和必要的受控测量。

长报表保留旧快照时，刚被业务删除的版本仍可能需要给它看。只调整autovacuum频率却不结束不必要长事务，清理也未必能前进；先查谁还需要旧版本，再判断维护是否跟得上变化速度。

## 观察一次更新与维护

在 L4 练习表上更新一部分记录，记录更新前后大小、死元组估计和计划。结束所有旧事务后，在事务块外执行：

```sql
VACUUM (ANALYZE) practice.orders_perf;
```

重新查询大小。文件没有明显缩小并不表示失败；观察空间是否能被后续写入复用、统计是否更新、Index Only Scan 的 heap fetch 是否变化。不要要求统计在每一瞬间精确反映刚刚写入。

## 分区主要帮助裁剪与生命周期管理

按月分区后，查询一月数据可以只访问相关分区，过期整月也有独立生命周期。但不带时间条件的点查仍可能访问多片，本机分区也仍在同一数据库上。收益来自裁剪与管理范围，不是表名分开以后所有查询都更快。

```sql
CREATE TABLE practice.events (
    id bigint NOT NULL,
    occurred_at timestamptz NOT NULL,
    payload jsonb NOT NULL,
    PRIMARY KEY (occurred_at, id)
) PARTITION BY RANGE (occurred_at);

CREATE TABLE practice.events_202601 PARTITION OF practice.events
FOR VALUES FROM ('2026-01-01 00:00:00+00') TO ('2026-02-01 00:00:00+00');
```

PostgreSQL 的分区表唯一约束有分区键限制，不能照搬原来单列主键设计。上例主键包含时间，所以不能保证 `id` 跨不同月份全局唯一。业务需要单一全局身份时另行设计约束来源。

把id放到两个不同月份，即使相同，复合主键也不同。若应用仍按单个id当作唯一身份，模型与接口就已经不一致；分区不仅影响性能，也会改变可由原约束保证的规则。

要提前创建未来分区，监控无匹配分区导致的插入失败。分区过多增加规划和维护成本。默认分区能接住遗漏范围，但可能掩盖管理缺陷并影响后续挂载，使用前明确维护流程。

## 归档先保证能找回

定义保留期、查询需求、法律留存、脱敏与恢复办法；导出后核对记录数、校验和、时间范围及读取能力，再进行分区移除或删除。备份里的旧数据也受保留与访问管理约束。

归档完成不是文件生成完，而是按要求还能读取与恢复。先保留证据，再移除在线数据，才能在业务要查历史时说明记录去了哪里；缩小主库文件不能成为丢失创作或业务成果的理由。

## 动手验证

说明大批量删除后空间为什么没有归还，以及长期不提交的报表事务会有什么影响。为一年事件数据设计月分区，分别展示带时间条件和不带时间条件的 `EXPLAIN`，比较扫描分区。

参考：[日常维护](https://www.postgresql.org/docs/16/routine-vacuuming.html)、[分区](https://www.postgresql.org/docs/16/ddl-partitioning.html)。
