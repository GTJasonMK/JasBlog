    Python 10：异常处理：在哪里接住失败

    异常处理要回答的是：这一层能不能对失败做出有意义的处理。能给出输入提示就转换成清楚的错误，不能恢复就保留原因往外抛，别用一个空的 except 把失败藏起来。

  2. 学习笔记2026-11-12

    Python 11：文件、路径与编码：先确认读写的对象

    文件找不到时，我会先检查当前工作目录，再检查文件名。相对路径跟着进程的工作目录走，和脚本存在哪个目录没有必然关系，这一点比反复改路径字符串更值得先确认。

  3. 学习笔记2026-11-12

    Python 12：JSON、CSV 与序列化边界

    能把文本解析出来，只说明它符合 JSON 或 CSV 的格式；字段是否齐全、数量是否有效，还需要另外检查。我会把解析和业务校验当作两个步骤。

  4. 学习笔记2026-11-12

    Python 13：模块、导入与程序入口

    我希望一个模块被导入时，能安全地提供函数和类型，而不是突然开始读文件、问用户要输入。把运行入口收进 main，是控制这类副作用的简单办法。

  5. 学习笔记2026-11-12

    Python 14：类、属性与数据类：什么时候需要一个对象

    我不会因为代码多了就立刻建一个类。几项操作确实共享同一组状态，或者需要一起维护某个规则时，把它们放进对象才有意义；只做转换的逻辑，用函数就够了。

  6. 学习笔记2026-11-12

    Python 15：组合、继承与协议：依赖需要的行为

    通知功能需要的是“能发送消息”，不一定要知道发送者属于哪个继承体系。我更愿意先把需要的行为说清楚，再决定用组合、协议还是继承来表达。

  7. 学习笔记2026-11-12

    Python 16：迭代器与生成器：数据不必一次准备好

    处理日志这类逐条消费的数据时，我通常不需要先把所有结果装进列表。生成器可以处理到哪里就产生到哪里，不过它已经走过的部分不会自动重来。

  8. 学习笔记2026-11-12

    Python 17：装饰器与上下文管理器：把公共动作放在合适的位置

    有些动作发生在函数调用前后，比如计时；有些动作发生在一段代码进入和退出时，比如释放锁。我会先区分这两个范围，再选择装饰器或上下文管理器。

  9. 学习笔记2026-11-12

    Python 18：常用标准库：先看操作，再选工具

    碰到计数、分组或队列处理，我会先翻一下标准库。Counter、defaultdict、deque 解决的问题很具体，用它们通常比自己维护一套相同的状态更容易读。

  10. 学习笔记2026-11-12

    Python 19：正则、日期与时间：格式之外还有语义

    提取一个固定格式的编号，可以用正则；表示一次真正发生的事件，还得考虑时区。我的判断是：先确定数据想表达什么，再选字符串方法、正则或时间类型。

  11. 学习笔记2026-11-12

    Python 20：命令行、子进程和 HTTP：处理外部输入

    脚本一旦要接收参数、调用程序或访问接口，就开始和外部环境打交道。我会把超时、返回状态和输入校验放在调用边界，后面的转换函数只处理已经确认的数据。

  12. 学习笔记2026-11-12

    Python 21：虚拟环境与项目结构：让依赖跟着项目走

    遇到“明明装了包却导入失败”，我会先核对运行程序和安装依赖用的是不是同一个解释器。虚拟环境就是为了让这件事和每个项目绑定，而不是依赖机器当前碰巧装了什么。
