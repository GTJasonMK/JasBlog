    数据库 11：按查询设计索引，也把写入代价算进去

    索引要从具体查询反推。比如查某个客户最新的已支付订单，筛选、排序和返回字段都影响键的顺序；多建一个索引，还会增加每次写入和后续维护的成本。

  2. 学习笔记2026-11-13

    数据库 12：从执行计划解释查询为什么慢

    接口慢时，我会先分清时间花在连接池、锁等待，还是 SQL 执行上。确定语句和参数之后，再沿执行计划找工作量开始放大的位置，用同一查询的前后结果验证判断。

  3. 学习笔记2026-11-13

    数据库 13：删除后文件为什么没变小，分区又能解决什么

    删掉很多行，文件大小可能几乎不变。要解释这个现象，需要区分旧版本回收、空间复用和文件重写；分区则主要帮助裁剪查询与管理数据生命周期，不能代替这些维护工作。

  4. 学习笔记2026-11-13

    数据库 14：把连接身份、对象权限和数据安全分开检查

    设置了密码，并不意味着权限已经收好。我会分别检查谁能连进来、连接者是谁、能访问哪些对象，以及客户端是否验证了服务端身份，再用应该失败的操作验证边界。

  5. 学习笔记2026-11-13

    数据库 15：有备份文件之后，还要证明能恢复

    备份任务成功只是第一步。我会把备份还原到独立数据库，再核对金额、流水、约束和权限；行数相同不足以证明内容正确，小库恢复几秒也不能直接变成生产恢复承诺。

  6. 学习笔记2026-11-13

    数据库 16：用基础备份和连续 WAL 回到误删之前

    误删以后，恢复目标通常是错误发生之前的状态。这里用命名恢复点把位置说清楚，再把基础备份与连续 WAL 恢复到独立数据卷，通过两边不同的标记确认停在了哪里。

  7. 学习笔记2026-11-13

    数据库 17：副本有多新，切换时怎样避免两个主库

    副本存在，不代表主库故障时一定不丢数据。需要看提交等到了哪个阶段、副本实际追到哪里，以及切换时怎样隔离旧主。复制、备份和高可用分别承担不同的恢复责任。

  8. 学习笔记2026-11-13

    数据库 18：从业务延迟追到资源，再算容量预算

    我会先看请求成功率和延迟，再看连接、等待、SQL 与存储。CPU 不高时也可能已经锁住了整个下单流程，缓存命中率很高也可能只是反复扫描太多数据。

  9. 学习笔记2026-11-13

    数据库 19：用等待链、计划和存储证据定位故障

    排查故障时，我会先记下影响范围和最近变化，再逐个检验假设。重启后恢复只能说明现象改变了，原因仍要靠等待链、查询计划或资源变化解释。

  10. 学习笔记2026-11-13

    数据库 20：从调用方到历史数据，完成一次可核对的迁移

    新增一个必填字段，会同时影响旧数据和新的写入请求。我会先找齐调用方，再安排加列、更新写入、分批回填和收紧约束，每一步都要知道失败后保存了什么、从哪里继续。

  11. 学习笔记2026-11-13

    数据库 21：把 PostgreSQL 的经验迁到 MySQL 时，要重查哪些行为

    两套数据库都支持事务，默认隔离、行版本、范围锁和 DDL 行为却不一样。这里限定 MySQL 8.4 与 InnoDB，用具体操作对照差异；这些 SQL 需要独立的 MySQL 实验实例。

  12. 学习笔记2026-11-13

    数据库 22：什么时候该加缓存、分析库或分片

    系统变慢以后，我会先找出单库究竟卡在哪里，再考虑增加组件。缓存、分析库和分片各自解决一部分负载，也各自增加同步、权限、故障恢复和数据核对的工作。
