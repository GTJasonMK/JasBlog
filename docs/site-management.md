# 站点与内容管理

在 JasBlogEditor 桌面应用中选择博客根目录。编辑器的内容、摄影和站点入口分别管理文章、摄影作品及网站文案和导航；页面模板与布局由博客代码维护。

## 站点与页面

站点数据保存于 `content/site.json`，包括名称、介绍、首页文案、页脚、各栏目的标题和说明、公开状态、导航及 Giscus 配置。凭据继续由 Git 和 GitHub CLI 管理，不写入站点配置。

导航隐藏只移除入口，原地址仍可访问。栏目停止公开后，其列表、详情、首页引用和搜索结果都不再生成。首页始终公开。停止公开不会删除 Markdown 或照片原片。

通过“新建 → 独立页面”创建关于、联系等正文页面，地址为 `/pages/<文件名>`。修改标题不影响地址；修改文件名会使旧地址失效。导航引用页面前须先创建页面，移除或重命名前须先移除导航引用。

## 内容与素材

新内容默认 `publication: draft`，设为 `published` 后参加下一次构建。规划的任务 `status` 与发布状态相互独立。笔记和独立页面支持 `display.cover`、`display.toc`、`display.comments`；实际评论还受站点总开关控制。

图片通过编辑器选择或拖入，填写描述后插入正文。生成文件位于 `public/media`；摄影作品位于 `public/photography`。生成图片去掉 EXIF/GPS 并纠正方向，原片不修改。摄影批次逐项保存进度，同一次请求恢复时复用已生成图片，不覆盖已完成作品。

预览包含明确标记的草稿；栏目列表预览只展示公开内容。编辑器不连接真实评论线程。

保存会核对磁盘版本。发现外部修改时保留编辑草稿，提供另存和重新载入；本地恢复记录位于应用数据目录。修改内容后未保存也不会因切换文件直接丢失。重新载入前保存恢复副本。

文本字段使用字符串，空值写作 `""` 或省略；`tags/companions` 使用字符串数组，`techStack` 使用包含 `name` 的对象数组。项目和图谱使用 `name`，规划使用 `title`。日期为有效的 `YYYY-MM-DD`，日志时间为 `HH:MM`。非法字段保留原文并明确提示，不会转为默认值后覆盖保存。

## 一键发布

本机需要 Node 20 或更新版本、Git、GitHub CLI。先在博客目录执行 `npm ci`，完成 Git 身份配置和 `gh auth login`，确认 Git 能向 origin 推送。编辑器只支持无内嵌凭据的 GitHub SSH 或 HTTPS origin。

点击“发布”先保存当前内容并展示变更范围，再点击面板中的“发布”。流程依次构建、提交、推送、跟踪博客工作流、跟踪 Pages 工作流，最后核对线上 `deployment.json` 的源提交 SHA。

受管提交只包含站点配置、各类 Markdown、摄影清单及生成素材。源码修改、冲突、未知未推送提交和非内容暂存项会阻止发布。编辑器不自动合并、变基或强推。

推送或状态查询中断后，可恢复同一提交。明确点击恢复发布可重试失败的工作流，不重新创建内容提交。构建快照与暂存或提交结果不一致时阻止推送，保留本地结果供人工核对。部署阶段查询权限不足时显示未确认，不当作成功。

恢复提交校验 Git 中的文件集合与内容指纹，不要求当前工作区仍等于旧快照，恢复期间的新编辑保持未提交。异常提交须先人工核对并撤回至发布前的父提交，再重新发布。

`npm run commit:content` 使用同一发布实现，也会执行构建与部署状态核对。不要用它测试当前开发工作区。

## 升级已有内容

```sh
npm run site:migrate
```

该命令只为尚未声明状态的现有内容写入 `publication: published`，创建原始备份及迁移记录，保留 YAML 注释、未知字段、BOM 和换行。重复执行不会重复修改。默认备份位于 `.run/site-migration`，可传入其他备份目录。

运行时不会自动把缺少发布状态的内容视为公开。公开内容配置错误会阻止发布；草稿保留可编辑状态。静态导出从空目录生成，停止公开的旧文件和仅被草稿引用的受管图片不进入部署产物。
