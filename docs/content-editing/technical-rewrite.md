# 技术文章重写

本轮范围是学习笔记中的 Python、Go、TypeScript、数据库四个系列，共192篇，包含知识讲解、项目、练习及附录。用户提供的《情书》影评用于理解叙述方式，技术文章仍以准确、可验证的知识解释为依据，不编造作者经历。

## 写法

让段落之间有实际的推理关系。遇到一个现象，说明原先容易怎样理解，用例子检查这个理解，再解释原因和使用条件。概念须交代含义，作用须对应具体问题，适用场景须说明选择依据及限制。代码前说明要观察什么，代码后解释结果为什么出现。需要的前置知识在本篇交代，扩展内容可以链接到其他文章。

删掉机械的第一人称开场、只有名词没有解释的清单、重复的结尾和泛泛而谈的建议。小标题按本篇的内容组织，不统一套“概念、作用、场景”三段模板。口语表达服务于理解，不强加吐槽。篇幅按知识完整性决定，短章补足解释，已有完整实验和参考材料保持其用途。

## 内容与地址

逐篇阅读后修改正文和摘要，保留文章地址、分类、首次发布时间及原始资料。需要调整代码时说明原因并验证；保留教程项目的演示属性和实验记录的原始条件。能通过连贯叙述补足的文章先独立完善，必要的合并须同时处理目录、前后篇及引用，避免留下空文章或重复正文。

## 完成证据

每篇记录实际改写范围及概念、作用、场景的检查结果。文字扫描、字符数和构建只提供辅助证据，不能证明叙述质量或技术完整。对新增或改动的可执行示例进行相应验证，核对元数据、内部链接、附件及系列顺序，再检查真实页面。全量工作完成前不将抽样通过表述为全部完成。

工作进度和改写前摘要保存在忽略目录 `.run/technical-rewrite`，供中断后继续；已完成内容不重复生成。
